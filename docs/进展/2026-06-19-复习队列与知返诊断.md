### 4. 复习防刷（重要修复）
- 发现 bug：复习是「重开新 session 跑老题」，提交通过会无条件发 `on_mine_fixed`（+3 Independent_Debug），
  反复复习同一题就**刷高 Debug 能力分、污染数字孪生**。
- 修法：review 模式 submit **跳过所有能力增益事件**（on_mine_fixed / 迁移确认 / 知识升级），
  但 `ExecutionEvent` 照常记（驱动间隔升档）。已验证：review 提交 0 能力事件、debug 照常 1 个。
- 语义点（待后续）：当前 review 只完成「间隔复习队列闭环」，**不**推动 已解决→已内化；
  将来要强化「内化」须单独设计 retention/内化验证事件，不复用首次解题能力分。

## 二、发现但没修的（已记入记忆，单独开轮）

### 🔴 知返对话期不跑代码 → 自信编造代码输出（幻觉）
- 实例（BP-LOOP-001 验证阶段）：学生提输入 `[5]`，知返答「预期就是 [5]，这个也通过了」，
  真相是 `countdown([5])` → TypeError。知返凭空编执行轨迹、假宣布通过、还幻想出不存在的「列表版本」。
- 病根：对话期知返没有沙箱，只能脑补，且脑补错还很笃定。对零基础是重伤（自信地教错事实）。
- 与本轮改动无关（tutor.py 没动），是早就存在的质量问题。
- 修法方向：把路线 A 沙箱用进 ⑤验证对话——学生提测试输入先真跑、把真实结果喂给知返
  （复用提交失败时 `judge_feedback` 的机制），让它据真相引导。+ 补红线「未经真实运行不准断言输出」。

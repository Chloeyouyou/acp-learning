## 1. 知返回复质量守门

涉及文件：

- `backend/app/services/tutor.py`
- `backend/run_tests.py`

新增数据结构 `ReplyGuardResult`：

```json
{
  "passed": true,
  "violations": [],
  "question_count": 1,
  "route_observed": true
}
```

触发位置在 `run_turn` 调用模型之后、回复写入会话历史之前。守门检查三类可确定判定的问题：

- `direct_fix_leak`：回复直接包含题库 `expected_fix`，包括“方案 A 或方案 B”中的任一方案；
- `question_count` / `question_not_at_end`：整段回复必须只留一个问题，且问题位于结尾；
- `route_not_observable`：学生表示听不懂后，策略虽然声明换路，但回复没有真实出现比喻、微型例子、执行链或对比结构。

首次违规会把违规原因作为隐藏的系统纠错信息，要求模型完整重生成一次。第二次仍违规或重试异常时，只替换对学生可见的 `reply` 为当前阶段的安全小问题，不改变模型对进展、事件和阶段的结构化判断。

每轮结果写入 `session_messages.meta.reply_guard`，同时随接口响应返回：

```json
{
  "passed": false,
  "attempts": 2,
  "fallback_used": true,
  "violations": ["direct_fix_leak"],
  "final_question_count": 1
}
```

## 2. 浏览器关键链路

涉及文件：

- `frontend/playwright.config.js`
- `frontend/e2e/critical-flows.spec.js`
- `frontend/package.json`
- `frontend/package-lock.json`

新增两条 Chromium 冒烟用例：

1. 学生在身份页输入学号和姓名，获得有效身份并进入练习场；
2. 创建边界题会话，运行带雷代码得到 `IndexError`，提交正确代码，再分别从学生回放和教师钻取看到同一个关键突破、动作证据和恢复指标。

测试使用独立的 `acp-e2e.db`、本地 subprocess 沙箱和测试管理口令，不读取开发数据库，也不调用真实 DeepSeek。

## 3. GitHub Actions 质量门

涉及文件：

- `.github/workflows/quality-gates.yml`
- `.gitignore`

触发条件：

- push 到 `main` 或 `feat/**`；
- 向 `main` 发起或更新 pull request。

流水线按顺序执行：后端全量测试、空库 Alembic 升级与漂移检查、前端依赖锁安装、生产构建、Chromium 安装、浏览器关键链路。失败时保留 Playwright report、截图和 trace，保留 7 天。

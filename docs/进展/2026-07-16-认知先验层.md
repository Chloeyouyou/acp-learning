# 2026-07-16 认知先验层（三层记忆第三层雏形）

分支 `m-prior-layer`（基于 m-exp-memory）。计划见 `docs/计划/2026-07-16-认知先验层计划.md`。

## 做了什么

- **S1 `app/priors/` 核心包**（976f98f）：store/distill/inject 三模块，只依赖标准库，
  LLM 以 callable 注入。三条硬门槛全是确定性规则，不押模型自觉：
  - 3 证据门槛（source_id 去重，同源刷次数不算）；
  - 临时态隔离（transient 进临时区、48h TTL、永不固化——「今天很累」不许变成人格）；
  - 反例退休（active 累计 2 次独立矛盾 → retired 留档；候选被打脸 2 次直接出局）。
  - 注入措辞由包内强制生成：仅供选择讲解起点 / 本轮矛盾以本轮为准 / 绝不贴标签。
- **S2 宿主接线**（0b7b112）：`services/prior_adapter.py` 是唯一认识 priors 的宿主代码；
  tutor.py 两钩子——结算沉淀经历后喂蒸馏、build system 时注入 active 先验。
  失败关闭（蒸馏炸了不波及结算）；`ACP_PRIORS=off` 保险丝；`ACP_PRIORS_DIR` 挪目录；
  数据在 `backend/priors_data/{student_id}.json`（gitignore，人类可读可手删）。
- **测试**：独立 `test_priors.py` 14 项全绿（假 LLM，含「包内不得 import 宿主」的
  拆卸纪律自动化检查）；主套件 125 过 0 败。
- **S3 真 LLM 端到端**：喂 3 条同倾向经历摘要，DeepSeek 三次归到同一候选、
  第 3 条独立证据准点晋升 active，注入文本硬规则齐全。产出示例：
  「他倾向于先直接修改代码再读报错信息，而非先分析错误原因。（推断自 3 次经历）」

## 踩的坑（重要）

- 主套件的结算路径测试会真触发蒸馏——`.env` 有真 key 时单测打了真网、
  还把测试学生档案落进了真 `priors_data/`。修法：run_tests.py 顶部
  `os.environ.setdefault("ACP_PRIORS", "off")`，先验行为由 test_priors.py 假 LLM 单独锁。
- run_tests.py 当时带着主线四轮的未提交改动，用 `hash-object + update-index`
  只把这 3 行 staged 进提交，没有裹挟别人的工作。

## 设计要点（讨论定的，别回退）

- 先验层是**独立于灵犀和蒸馏的第三种东西**：蒸馏是生产者，先验档案是资产，
  应用只是消费者。第一宿主 ACP，灵犀等有第二消费者时再拆包（Rule of Three）。
- 置信度不写数字——证据条数与新旧就是置信度；`stated`（明说）/`inferred`（推断）
  的来源区分代替置信度字段。
- 覆盖序：当前明确表达 > 当前情境 > 长期先验 > 通用默认，措辞里写死。

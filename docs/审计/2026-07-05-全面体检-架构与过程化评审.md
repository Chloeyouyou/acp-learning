## 一、结论先行

**「过程化」的骨架已经建成，系统早已不是判题系统。** 事件溯源 + 六阶段门控 + 派生画像这套内核架构方向正确、实现质量高。真正的升级不是重构理念，而是补三块：

1. **代码快照** —— 让过程可回放（事实源里目前缺了最核心的事实：学生每一步的代码）
2. **身份 + 沙箱隔离** —— 让它能安全地见真实学生
3. **课程层** —— 让它从「一堆题」变成「一个产品」

## 三、还缺什么（按重要性）

1. **过程数据只有「结果链」，没有「代码链」**。ExecutionEvent 记了每次 run/submit 的 kind，但**不存学生当时的代码**。无法回放解题过程、无法 diff 分析（盲改 vs 定向改）、无法支撑数字孪生。这是「过程化」最大的空洞。
2. **无真实身份与授权**。student_id 前端自报（localStorage），任何人换 URL 可读任何人画像/对话史（= 6-22 审计 #3 IDOR，VPS 开放后已从欠账升级为漏洞）。「登录后记录没了」的遗留 bug 大概率同根：自报 id 不一致。
3. **无课程/路径层**。23 题平铺，选题靠画像贪心；没有单元→关卡→里程碑结构，学生无地图感、教师无法布置。
4. **无教师/班级视角**。所有派生视图都是学生自视角，进不了真实课堂。
5. **无 schema 迁移机制**。只有 create_all；mode 寄存 manifest JSON「零迁移」是权宜，字段一多必失控。
6. **单文件单语言**。多文件项目、stdin 交互题型不支持（可后置）。

## 四、最大技术风险（排序）

### 🔴 R1 沙箱不隔离（部署给真学生前必须解决）

`sandbox.run_code` 用服务器同一用户直接跑学生代码，只白名单了环境变量（挡住了偷 key，但仅此而已）。学生代码可 `open('acp.db')` 读全班对话史、删文件、发网络请求、fork 炸弹耗尽 VPS。coop「粘贴自己的代码」入口让攻击面更大。单人自用没事，**开放真实学生就是事故**。

### 🔴 R2 同步阻塞 + SQLite 并发丢写

全部端点同步 def，LLM 调用（30s 超时）在请求线程里做；`session.history` 整块 JSON 每轮重写、无行级锁/乐观并发。30 人同时对话：线程池耗尽、SQLite 写锁竞争、同一 session 并发两请求互相覆盖 history（丢消息）。= 6-22 审计 #12 TOCTOU 的放大版。

### 🟠 R3 LLM 单点

DeepSeek 硬编码、无流式（学生盯 10 秒空屏）、无备援、无限流。规则层兜了 ①②④⑤，但 ③⑥ 关键判定完全依赖 LLM 的 JSON 报告。

### 🟠 R4 派生视图 O(N) 增长

`build_timeline` 每次全量拉该生全部 session+event，而 `intervention_for` 在**每次开题**都调它。一学期数据量后开题明显变慢。

### 🟡 R5 两个上帝文件

tutor.py（880 行：模板+规则+状态机+LLM 客户端+缓存混居）、Arena.vue（1504 行）。逻辑没错，但改动成本与回归风险持续上升；main.py 还承载 submit_fix 完整业务流。

## 五、保留 / 重构 / 删除清单

**原样保留（核心资产）**：四张事件/派生表 schema、event_engine、registry、profile、timeline、review、presence、question_training、六阶段状态机逻辑与全部剧本文案、23 道 YAML + validator 闸门、84 个测试断言体、前端 5 视图交互设计。

**重构（逻辑保留、形态改变）**：
- main.py（539 行）→ api/ 路由层 + submit_fix 流程下沉 service
- tutor.py → prompts.py（纯数据）/ rules.py（正则判定）/ state_machine.py（跃迁门控）/ llm.py（客户端+流式+降级）
- Arena.vue → ArenaView 编排 + CodePanel / ChatPanel / StageTracker / RunConsole 组件
- session.history 整块 JSON → session_messages 表（治 R2 丢写 + 无限膨胀）
- sandbox → 容器实现（接口不变，subprocess 留作本地 dev fallback）

**删除（死代码）**：`tutor.diagnose_failed_fix`（自注明已被取代）、`mine_engine.verify_fix`（无人调用的兼容壳）、manifest 里的 `fix_check` 传递（真跑判题后运行时不再需要，仅生成期质检用）、smoke_test.py 与 run_tests 重叠部分。

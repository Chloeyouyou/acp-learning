# 06 · 学生数字孪生 MVP 设计方案 **v2**（路线 B）

> v2 增补（基于评审意见）：事件溯源章、Mastery+Confidence 双维、Struggle 信号规范、Debug Timeline、知识点图谱接口、自进化闭环。未来预留接口详见 `07-未来演化接口设计`。

## 背景与目标
当前画像（`05`）只到两层：9 项能力分 + 知识点×模式状态机。它能说"你 Debug 62 分"，说不了"你**哪个知识点还不稳**、下一步练什么"。路线 B 升级成**以知识点为最小单位的掌握模型**，发现薄弱点、精准推荐复习。

**理念（不可违背）**：struggle 信号只驱动"要不要再练"，**绝不扣能力分**。学习工具不是考试。

---

## 0. 事件流唯一事实源（Event Sourcing）—— 架构地基
- `capability_scores` 是**派生视图**；新增的 `knowledge_mastery` 也是**派生视图**。
- **所有画像都必须能由事件流（append-only 的 `events`）重新计算/回放得到。**
- **不允许把掌握度当"最终状态"写死**——即不允许出现"只改掌握度、不留对应事件"的写法。
- **性能 nuance（重要）**：允许把派生视图**缓存**（capability_scores 现在就是缓存），但缓存必须**任何时候都能从事件流重建**。原则是「事件是事实源、视图可重算」，不是「禁止一切存储」——否则每次看画像都全量回放会拖慢。
- **为什么**：未来要引入遗忘曲线 / 知识追踪 / 贝叶斯 / 自适应学习，必须能重放事件流换算法。把掌握度计算、推荐保持成**单独可替换的函数**（如 `profile.get_profile` / `recommend_patterns`），换模型不动状态机、不迁 schema。

---

## 1. 学生画像由哪些事件驱动？
复用现有事件流，**不新增事件类型**（除可选的 `Execution_Outcome`，见 07/A-3），更充分用已带字段：

| 信号 | 来源（现有） | 用途 |
|---|---|---|
| 能力事件 capability+delta | Root_Cause_Reasoning / Hypothesis_Testing / Independent_Debug / Boundary_Awareness / Internalization / AI_Verification | 正向掌握证据 |
| `context.knowledge_points` | 事件落库时带 | **把事件归并到知识点**（B 核心维度） |
| `context.hint_level` | 已记 | struggle 信号（不扣分） |
| confidence / producer | rule=1.0 / llm_judge<1 | 证据可信度加权 |
| 知识点状态 | knowledge_states | 掌握档位硬锚点 |
| 迁移已验证 | `on_transfer_confirmed` | 最强掌握证据 |
| 判题结果(A) | `judge_fix` 的 kind/stderr | struggle 信号 + Execution_Outcome 种子 |
| Debug Timeline | 见 §6 / 07-A-1 | "怎么解决的"过程信号 |

## 2. 能力分如何计算？—— Mastery + Confidence **双维**（不压成一个等级）
评审要求：不要把信息压缩成单一等级。每个知识点输出**两个独立维度**：

- **Mastery 掌握度**（会不会）：`生疏 / 在学 / 掌握 / 熟练`
  - 生疏：没碰过 / 只"已接触"无正向事件
  - 在学：有正向事件但未内化
  - 掌握：相关模式"已内化"
  - 熟练：已内化 **且** 迁移已验证
- **Confidence 稳定度**（稳不稳）：`高 / 中 / 低`
  - 由 struggle 信号 + 表现波动决定：靠高提示通过、被勉强放行、多次提交失败、最近做得反复 → 稳定度低。
  - **稳定度低不降 Mastery 档位**，只表示"会做但最近波动大 / 还不牢"。

例：`边界意识 — 掌握度：熟练，稳定度：低` = 会做，但最近波动大，建议复习。

> 现有能力分（capability_scores）保留作粗粒度概览；knowledge_mastery 是新增的细粒度派生视图。两者都可下钻到支撑事件（延续"每个数字有出处"）。MVP 用**透明规则**聚合，不上 ML。

## 3. 如何发现弱点？
对每个知识点排「该练优先级」（规则透明、可解释）：
```
生疏 > 在学且稳定度低 > 在学 > 掌握但到期复习 > 熟练(基本不推)
```
输出「薄弱知识点」有序列表，每条带人话理由（"『循环不变式』你通过时用了很多提示，稳定度低，建议再练"）。

## 4. 如何按弱点推荐下一题？
升级 `profile.recommend_patterns`：从"按弱能力"→"按薄弱**知识点**"：
- 取最该练的知识点 → 找 `knowledge_points` 含它、未内化的题；
- "稳定度低但已通过" → 优先走变式/复习路径；
- "到期复习" → 已内化题的变式巩固；
- 每条带知识点维度的理由；无明显薄弱点时按难度推进新知识点。

## 5. 前端页面
能力画像页（`Profile.vue`）**新增「知识点掌握度」区**，不动雷达/能力明细：
```
▸ 知识点掌握度
  数组       掌握    稳定度 高                    [去练→]
  循环       在学    稳定度 低 ⚠建议再练           [去练→]
  循环不变式  生疏                                [去练→]
  字典       熟练 ✓迁移已验证  稳定度 高
  （点知识点 → 下钻看支撑它的具体事件）
```
- 每行：知识点 + Mastery 档位 + Confidence + 稳度标记 + 「去练→」（复用 `?start=`）+ 可下钻。
- 薄弱排前带理由；熟练靠后。智能推荐理由同步改知识点维度。

## 6. Debug Timeline（新增，B 的重要燃料）
除能力事件，记录一次解题的**过程**（不只结果）：first_run 时间、每次提交时间、RE/WA/HANG、提交次数、修复耗时。
> 让系统能回答「这个学生**是怎么**解决问题的」。MVP 先记最基础的（时间戳 + 提交序号 + outcome + 修复耗时，数据 A 已有），`edited_lines`/locals 等留 07。详见 `07-A-1 / A-2`。

## 7. Struggle Signal 扩展规范
**现记**：提交次数、提示等级、判题 kind、是否被⑤安全网勉强放行。
**预留补充**：修复耗时、放弃次数、回退次数、⑤验证失败次数。
**铁律**：这些信号**只影响推荐优先级（Confidence/该练优先级），永不直接扣能力分**。

## 8. 知识点图谱接口（预留，MVP 不实现）
知识点**现在是平面字符串**，但**别写死**。预留图结构（详见 `07 知识图谱接口`）：
```
Boundary_Check ├ prerequisite: [Loop, Array_Index]  ├ related: [Off_By_One] └ patterns: [BP-BOUNDARY-001,003]
```
> MVP 仍读平面字符串；图结构作为可选元数据层叠加，老数据平滑升级。**现在别建整张图**（无底洞），只留 schema。未来接知识图谱 / 迁移分析 / 本体建模。

## 9. 自进化闭环（Self-Evolving Loop，只写架构）
```
事件流 → 数字孪生(B) → 薄弱点发现 → 自动出题(E) → 训练 → 新事件流 → 画像更新
```
B 暴露「薄弱点列表」给 E；E 按薄弱点生成题、用 A 沙箱质检；各模块只经事件流与边界通信。详见 `07-A-5`。

## 10. MVP 最小实现范围
**做：**
1. 后端：`knowledge_mastery` 派生视图函数（事件→每 kp 的 Mastery+Confidence），放 `profile.py`，**单独可替换**。
2. 后端：事件 context 补记 struggle 字段（submit_attempts/rescued/hint_level 已有）+ 基础 Debug Timeline（时间戳/提交序/outcome/耗时）+ 可选 `Execution_Outcome` 事件（A-3，最便宜）。
3. 后端：弱点排序 + `recommend_patterns` 升级为知识点驱动 + 理由。
4. 前端：Profile 新增「知识点掌握度」区（双维 + 去练 + 下钻）；智能推荐理由改知识点维度。
5. 全程"提示不扣分、struggle 只驱动复习"。

**不做（留 07 / 后续）：** 真遗忘曲线/间隔重复算法、贝叶斯知识追踪/ML、Trace Snapshot 填充、Error Embedding、知识图谱建图、教师看板。

**验证：** 用真实事件数据对老账号算掌握度人工核对；"靠高提示通过"→该 kp 稳定度低且被推荐复习；已内化+迁移→熟练不再推；掌握度是事件流纯派生（删事件重放结果一致）。

---

## 与"自进化 / 本体演化"的衔接
本 v2 把掌握度做成**事件流可重算派生视图** + **可替换计算/推荐函数** + **知识点图谱 schema 预留** + **丰富的 struggle/timeline 记录**，正是自进化的四个接入点。将来换自适应难度、遗忘曲线、知识图谱、自调参，都只替换函数、消费同一事件流，不动状态机与 schema。**现在尽量丰富地记事件，是给未来留的最重要的口。**

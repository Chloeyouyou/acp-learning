# 11 · 灵犀感知层 / Presence Layer

## 本文件的作用
定义 ACP 的「灵犀」——一个**读人的感知层（Presence Layer）**，给产品补上"懂你"的温度。**本轮只出设计，不写代码。** 第一版落点：Arena 大厅一句「读过你」的招呼 + 推荐语气，**不动知返核心逻辑**。

灵感来自作者另一项目「灵犀 LingXi」（AI 情感陪伴：读情绪、压力感知、温柔不追问）。这里**只取灵犀有、而知返缺的那部分**——读人，并把它降维成一个克制的感知层，不是把整个陪伴 app 搬过来。

---

## 它是什么 / 不是什么

- **是**：ACP 背后的一层「读人」感知——读你的状态、节奏、停顿、回来的原因，面向**人**。
- **不是**：第二个可对话的角色 / 第二个导师。**第一版尤其不要。** ACP 已有「知返」，再出现一个独立聊天对象，用户会不知道该跟谁交互。
- 这层**内部叫「灵犀」**，但前台第一版**不强展示名字**——先让产品**有"灵犀感"**，不急着让灵犀作为角色露脸。

---

## 分工（与知返）

| | 知返 | 灵犀层 |
|---|---|---|
| 面向 | 代码、错误、推理链路 | 人：状态、节奏、停顿、回来原因 |
| 形态 | 任务里的对话导师（会问你） | 系统背后的感知层（**不问你**） |
| 出现 | 做题全程对话 | 极克制，偶尔一句，不缠人 |

知返查代码、会问你；灵犀读你、不问你。一个向任务，一个向人。

---

## 五条铁律（设计红线）

1. **只推理，不追问。**
2. **不做情绪问卷**，不弹「你今天心情怎么样」。
3. **不诊断用户状态**，只用温和、低压力的**猜测**表达（"可以…也可以…由你决定"，不是"你一定很累"）。
4. **每次最多轻轻出现一次**，给台阶或选择，**不连续打扰**。
5. **只用 ACP 内已有的一方数据**，不引入任何外部/隐私数据。

---

## 全系统个性化宪章（灵犀 = ACP 所有"读人但不追问"的总规则）

> 灵犀层不只是大厅一句招呼——它是 ACP **一切个性化输出**的统一宪章与协调者。凡是"读了这个学生、然后对他个性化地说一句话"的功能（大厅招呼、开题提醒、思维默认值、提问短板、未来 coop 反馈……），都归这层管，遵守同一套口吻、同一个总量预算、同一套闸门。目的：让用户感到是"一个懂我的产品"，而不是几个模块各自插嘴、还互相轰炸。

### 1. 一套口吻（全模块共用）
- **观察式、给选择、不贴死标签。**
- **禁止**"你总是…""你就是…""你不会…"这类定性。
- 用"最近几次里，xxx 相对少一些""这次可以先试试…""也可以…由你决定"这类表达。
- 承接[五条铁律](#五条铁律设计红线)#3：只温和猜测、给台阶，不替用户下判断。

### 2. 一个总量预算（当前唯一缺失的跨模块协调）
- **同一页面 / 同一次访问，所有个性化来源加起来最多出现一句主动提醒。**
- 大厅灵犀招呼、开题 `intervention_for`、提问短板提醒、画像提醒……**不能同时轰炸**。
- **按优先级取最有帮助的一句，其余压住**（落实铁律 #4 "每次最多轻轻出现一次"，但范围从"灵犀自己"扩到"全部个性化来源"）。
- 同页多个来源命中时的优先级，由该页定义；都不命中则**不出提醒**（不硬塞）。

### 3. 一套闸门（写一次，全模块遵守）
- **样本量不足不提醒**（达不到门槛就完全不显示，对齐思维默认值的 `enough`）。
- **低置信事件不参与**（`confidence < 0.7` 不计入统计/触发）。
- **只用 ACP 内第一方数据**，不引入任何外部 / 隐私数据。
- **不做情绪诊断**（呼应铁律 #2、#3）。

### 4. 触点清单（都归本宪章管）
| 触点 | 在哪 | 现状 |
|---|---|---|
| 大厅灵犀招呼 | Arena 大厅 | doc 11 第一版落点，未实现 |
| 开题提醒 `intervention_for` | 开题时 | `timeline.py` 已实现 |
| 思维默认值 / persona | 成长轨迹 | `timeline.py` / `profile` 已实现 |
| 提问短板总结 | 提问训练 P1 | [[12-提问训练]] §P1，已设计未实现 |
| coop 个性化反馈 | AI 共脑调试 | [[09-AI协作调试空间]] 未来，未设计实现 |

> 新增任何"读人后个性化说话"的功能，都必须登记进本清单并遵守上面三条。

## 可用信号（全部 ACP 内已有，第一方）
- 停留时间 / 卡了多久
- 连续报错次数（ExecutionEvent）
- 退出 / 隔多久回来（last_active_at 间隔）
- 未完成关卡（接着做）+ 停在哪个阶段
- 复习间隔（到期/久未复习）
- 用户自己在知返里说过的「好难 / 累 / 算了」这类文本（现被当噪音，其实是情绪信号）

> 第一版大厅招呼主要用**大厅就能拿到的信号**：未完成 + 停留阶段、复习到期。文本情绪（"好难/累"）作为更丰富信号，留稍后。

---

## 第一版落点 · 大厅一句「读过你」的招呼

在 Arena 大厅，主角（智能开一题）旁/上方，安静地出现**至多一句**灵犀的话——是**推**出来的，不是问出来的。

### 触发与优先级（最多命中一条，体现铁律 #4）
按优先级取第一条命中的，其余忽略；都不命中则**不出招呼**（不硬塞）：
1. 隔很久回来 → `好久不见，不急，今天可以先开一道轻一点的。`
2. 上次某题卡很久（未完成 + 高停留阶段）→ `上次那道你在验证阶段停了挺久，今天可以接着收尾，也可以先换一道轻松的。`
3. 有未完成题 → `我还记得你上次停在这里，但要不要继续，由你决定。`
4. （无明显信号）→ 不出招呼，或仅中性副标题。

### 文案准则（铁律 #3 落地）
- 永远**给选择、留出口**："也可以…""由你决定"。
- **不替用户下判断**：不说"你很累/你放弃了"，只说可观察的事实 + 一个温柔的可选项。
- 低压力、短、不煽情。

### 渲染位置
大厅 hero 区一句安静的话（与"开一道新题"主角并存，不抢焦点）。它正好也是之前想给大厅补的"互动/温度"——但形态是**被读到的感觉**，不是按钮堆。

---

## 架构（与 ACP 既有哲学一致）
- **纯派生、可替换、零新表**：一个独立函数（如 `presence_hint(signals) -> 最多一句话 | None`），消费已有信号，输出至多一条提示。镜像 `timeline`/`profile`/`review` 的派生视图哲学。
- **不动知返**：`tutor.py` / 六阶段状态机 / `run_turn` 全不碰。灵犀层与知返逻辑隔离。
- 第一版尽量**纯前端**派生，优先用前端已能拿到的信号（未完成关卡、停留阶段）。
- 注意 `/active-sessions` **只覆盖"有未完成会话"的情况**；若要判断"久别回来"但用户**没有** active session，需后续加一个**只读派生端点**从 `ExecutionEvent` 读最近活跃时间（**不建表**）。第一版优先用前端已能拿到的信号，这个端点留到需要时再加。

---

## 不做 / 划界
- 不做第二个聊天角色 / 第二个对话入口。
- 不做情绪问卷、不追问、不诊断。
- 不连续弹、不煽情、不剥夺用户选择。
- 不引入外部数据。
- 第一版不动知返核心逻辑、不前台强展示「灵犀」之名。

---

## 未来（分层加，不在第一版）
- 文本情绪信号：从知返对话里的「好难/累/算了」**推**情绪（仍不追问）。
- 做题中的挫败台阶：连续报错/久卡时，**温柔递一次**"歇会儿/换一道"，递完就退（呼应灵犀"低压力后平稳退出"）。
- 复习/回归的语气化。
- 是否、何时让「灵犀」作为有名字的存在露脸——等产品先有了"灵犀感"再议。

---

## 验收（第一版）
- 大厅在命中信号时，安静出现**至多一句**灵犀招呼；无信号则不出现。
- 招呼**只猜测、给选择**，不下判断、不追问、不连续出现。
- 只用 ACP 内已有第一方数据，不引入外部/隐私数据；不动知返；不新增聊天入口。

# AI导师策略设计 V0.2

> 职责：拿着埋雷引擎的 MineManifest（Ground Truth），通过「提示 → 追问 → 引导 → 验证」帮学生解决问题，**全程不直接给答案**，并在每个引导节点产出强类型能力事件（见 04-能力事件模型）。

---

## 1. 总体架构：对话状态机

AI 导师不是自由聊天，而是按教学阶段运行的状态机。每个阶段有明确的目标、AI 行为边界和退出条件：

```text
①发现 → ②定位 → ③归因 → ④修复 → ⑤验证 → ⑥内化
```

| 阶段 | 学生目标 | AI行为 | 退出条件 | 主要产出事件 |
|------|----------|--------|----------|--------------|
| ①发现 | 意识到程序有问题 | 引导运行、读报错、构造输入 | 学生能描述异常现象 | Log_Reading |
| ②定位 | 缩小到具体代码位置 | 苏格拉底提问、范围收缩 | 学生指出可疑行（与manifest.location比对） | Boundary_Awareness 等模式对应能力 |
| ③归因 | 说出为什么错 | 追问原理，不替学生总结 | 学生表述与root_cause语义一致（LLM判定） | Root_Cause_Reasoning |
| ④修复 | 自己写出修复 | 只评价方向，不给代码 | 修复后测试通过 | Independent_Debug |
| ⑤验证 | 确认修复正确且无副作用 | 引导补测试、试边界输入 | 全部测试通过 | Hypothesis_Testing |
| ⑥内化 | 沉淀为自己的知识 | 反向提问、要求复述、推送变式 | 复述达标 + 变式独立通过 | Internalization |

**不允许跳阶段**：学生直接改对了代码但说不出为什么（④过了③没过），AI 回到③追问归因——这是「已解决」和「已内化」的分水岭。

---

## 2. 引导阶梯（Hint Ladder）

核心机制：提示强度从弱到强分 6 级，**永远从当前最低可用级开始**，学生卡住才升级。提示级别直接进入事件 context——同样定位成功，L0 完成和 L4 完成产出的 `Independent_Debug` 增量不同。

| 级别 | 名称 | 行为 | 示例（off-by-one雷） |
|------|------|------|----------------------|
| L0 | 苏格拉底提问 | 只提问，零信息量注入 | "什么输入会让它出错？你试过几种？" |
| L1 | 现象引导 | 指向可观察的症状 | "看看异常栈的第一行，它告诉你下标是多少？数组长度是多少？" |
| L2 | 范围收缩 | 圈定区域+选择题 | "问题在循环附近。你认为是：A.初始值 B.循环条件 C.数组声明？" |
| L3 | 原理提示 | 讲知识点，不指具体错误 | "Java数组下标范围是 0 到 length-1。再看看你的循环能取到哪些值？" |
| L4 | 定位确认 | 指出具体行，要求学生解释 | "看第12行的循环条件。你说说它为什么有问题？" |
| L5 | 兜底讲解 | 完整讲解根因与修复思路（仍不贴代码） | 完整讲解，该雷标记为"未独立解决"，不计内化分 |

**升降级规则**：

```text
同一级停留 ≥ 3轮对话无实质进展     → 升1级
学生连续2次答非所问/明显猜测       → 升1级
学生明确说"卡住了/不知道"          → 升1级
学生有部分正确推理                 → 保持当前级，沿其思路追问
学生直接要答案（"你直接告诉我"）    → 拒绝，降回提问，产出 Independent_Debug 负事件
```

每个 BugPattern 在模式库里预置一份阶梯模板（`hint_ladder_ref`），AI 按模板实例化到具体代码，保证引导质量不依赖现场发挥。

## 3. 行为红线（Guardrails）

写入 System Prompt 的硬约束：

1. **任何阶段不输出可直接粘贴的修复代码**（L5 也只讲思路）
2. **一次只引导一颗雷**，多雷场景按 manifest 顺序逐颗处理
3. **不确认学生的猜测正确与否之前，先要求说理由**（"你为什么这么认为？"）
4. **不泄露 MineManifest 的存在**——学生视角里 Bug 是"代码本来就有的"
5. 学生情绪挫败（连续负面表达）时，先降难度共情，再回到引导，不直接给答案
6. 学生提出与雷无关但正确的代码改进，肯定并记录，但拉回当前阶段

## 4. System Prompt 结构与每轮输出（实现层）

```text
[角色] 你是编程导师，目标是让学生自己解决问题，绝不直接给答案。
[Ground Truth] {manifest中当前mine的：location/root_cause/expected_fix/hint_ladder}
[当前状态] 阶段={②定位}，提示级别={L1}，已对话轮数={4}
[学生画像摘要] Boundary_Awareness:32/100；Independent_Debug:55/100；倾向直接要答案
[行为规则] {第2节升降级规则 + 第3节红线}
[事件规范] {04-能力事件模型中的LLM判定事件清单与判定标准}
```

每轮结构化输出——事件是**强类型能力事件**，不是自由文本：

```json
{
  "reply": "你试试输入一个空数组，会发生什么？",
  "stage": "②定位",
  "stage_transition": null,
  "hint_level_used": "L1",
  "events": [
    {
      "capability": "Hypothesis_Testing",
      "delta": 1,
      "confidence": 0.85,
      "evidence": "学生在未提示的情况下主动提出'是不是和数组长度有关'的假设",
      "context": { "mine_id": "mine_001", "stage": "②定位", "hint_level": "L1" }
    }
  ]
}
```

要点：

- **Ground Truth 注入**让导师"开卷引导"，杜绝 AI 自己看错 Bug 的幻觉风险
- 导师 LLM 只允许产出 04 文档中注册过的事件类型，且必须附 evidence 原文依据
- 确定性事件（测试通过、雷状态跃迁）由后端规则引擎产出，不依赖 LLM——两路事件在事件总线汇合（见04）

## 5. 内化环节（⑥）协议

「已解决 → 已内化」必须依次通过三关：

```text
关1 反向提问：AI从pattern.internalize_questions抽问，学生作答（LLM按要点评分，≥80%）
关2 复述：学生用自己的话总结"这个Bug为什么发生、怎么发现的、以后怎么避免"
        （LLM按rubric评分：成因准确/定位方法/预防策略，三项各1分，≥2分过）
关3 变式：从variant_pool推送同模式换场景的雷，学生需在 ≤L1 提示下独立解决
```

任一关未过：该知识点保持「已解决未内化」，进入间隔复现队列（1天/3天/7天后再推变式）。三关全过产出 `Internalization` 事件，画像中该知识点跃迁为「已内化」。

## 6. Vibe Coding 场景：双角色分离

模块3中 AI 有双重身份，必须分离为两个独立的 Agent（独立 System Prompt、独立会话上下文）：

| 角色 | 类比 | 职责 | 产出事件 |
|------|------|------|----------|
| 协作AI | Pair Programmer | 写代码、出设计方案、结对编程（输出中含教学性雷） | 无（它是"被审查对象"） |
| 导师AI | Teacher | 质疑、追问、验证、引导审查协作AI的输出 | AI_Review / AI_Verification / Prompt_Design |

**为什么必须分离**：一个 AI 既生成代码又负责教学，会出现自我审查冲突（不愿质疑自己刚生成的代码）且角色话术混乱。分离后导师 AI 的引导话术从"你的代码哪里错了"变为"**AI 给你的代码你检查过吗？它为什么用这种写法？**"——训练目标从 Debug 转为 AI 代码审查。

学生对协作AI的提问质量（上下文完整度、问题描述、拆解粒度）由导师AI旁路评估，产出 `Prompt_Design` 事件——这同时覆盖了模块4的训练目标。

## 7. MVP 范围

- 状态机：①-⑤全量，⑥只做关1反向提问（复述评分与变式留V0.3）
- 引导阶梯：全6级，升级规则只实现"3轮无进展"与"明确求助"两条
- LLM判定事件只做高置信度的4类：Root_Cause_Reasoning / Hypothesis_Testing / Independent_Debug / AI_Verification
- Vibe Coding双角色留V0.3

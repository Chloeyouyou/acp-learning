# 07 · 未来演化接口设计（预留，**不实现**）

## 本文件的作用
路线 A（沙箱真运行）已落地，它真正的身份不是"判题功能"，而是 **整个系统唯一可信的「行为观测层 / Observation Layer」**——所有真实运行、真实报错、真实判题都从这里产生。未来想做的「学生能力自进化 / 本体演化 / 数字孪生」，燃料全在这层数据里。

本文件**只定义未来要用的接口与 schema 预留**，明确「现在不实现、只留口」。目的：以极低的当前成本，避免把数据结构写死，导致以后难升级。

**总原则**：
- 不增加当前实现复杂度；只在「字段 / schema / 函数边界」上留口。
- 所有画像/掌握度都是事件流的**可回放派生视图**（见 06-v2 事件溯源章）。
- 现在就尽量**丰富地记录事件**（哪怕 MVP 只简单用）——给未来模型留足数据，是最重要的预留。

---

## Route A 扩展点（不实现，按"便宜→贵"排序）

### A-3 Execution_Outcome 事件（最便宜，建议做 B 时第一个落地）
现状：能力事件都由导师 LLM 产生（Root_Cause_Reasoning…）。建议新增一类**由系统真跑产生**的事件：
```json
{ "type": "Execution_Outcome", "kind": "RE|WA|HANG|ok",
  "error": "IndexError", "pattern_id": "...", "knowledge_points": ["循环","边界"] }
```
> 数据**现在已经存在**——`judge_fix` 已返回 kind/stderr。把它落成事件几乎零成本。
> 价值：统计"这个学生总是 RE / 总是 WA / 总是 HANG"，是 Debug Timeline 与弱点发现的种子。**不计入能力分**，只作观测/推荐信号。

### A-1 Debug Timeline（便宜，B 的重要燃料）
除能力事件外，按时间线记录一次解题的「过程」而非只有「结果」：
```text
14:03 first_run        IndexError
14:06 submit #1        RE (改了第4行)
14:08 submit #2        WA
14:10 submit #3        ok（修复耗时 7min，3 次提交）
```
预留字段（事件 context 里即可，无需新表）：`first_run_at`、`submit_seq`、`outcome`、`fix_duration`、`edited_lines?`。
> 让系统能回答「这个学生**是怎么**解决问题的」，而不仅是「最后有没有解决」。MVP 可先记最基础的时间戳+提交序号+outcome（cheap），`edited_lines` 等留后。

### A-2 Trace Snapshot（留字段，**实现不轻**）
预留一个 JSON 字段，存出错瞬间的现场：
```json
{ "line": 4, "locals": {"i": 3, "arr_len": 3} }
```
> ⚠️ 诚实预期：**留字段便宜，填充很重**——要拿到 locals 需要带追踪的执行（`sys.settrace` / 事后 post-mortem），且与沙箱交互。**现在只在数据模型留 `trace_snapshot` 字段（默认 null）**，实现留到真做"AI 复盘"时。
> 未来价值：AI 复盘、错误模式发现、数字孪生。

### A-4 Error Embedding / Personal Bug Ontology（远期）
未来：所有错误 → 向量化 → 聚类 → 自动浮现「边界问题 / 空值问题 / 类型问题」等个人化的 **Personal Bug Ontology**。
> 现在只需保证 A-3 的错误数据被完整记录（error 文本 + 上下文）。聚类/embedding 远期再做。这与「本体快照 / Ontology Snapshot」是同一脉络。

### A-5 Self-Evolving Difficulty Loop（与 E 自动出题联动）
目标闭环（只写架构，不实现）：
```text
事件流 → 数字孪生(B) → 发现薄弱点(如 Boundary=42)
      → 自动出题(E) 针对性生成边界题 → 训练 → 新事件流 → 画像更新(Boundary=56)
```
> 接口边界：B 暴露「薄弱点列表」、E 接收「薄弱点→生成约束」、判题用 A 的沙箱质检。各模块只通过事件流与这两个边界通信，不互相耦合。

## 知识点图谱接口（Knowledge Graph Interface，预留 schema）
**最重要的预留**：知识点**现在是平面字符串**（`["循环","数组","边界"]`），未来要升级成图节点，别写死。

预留结构（MVP 不实现，仍读平面字符串；未来 pattern/知识点可挂这层元数据）：
```yaml
knowledge_point: Boundary_Check
  prerequisite: [Loop, Array_Index]   # 前置知识
  related: [Off_By_One, IndexError]   # 相关点
  bug_patterns: [BP-BOUNDARY-001, BP-BOUNDARY-003]  # 关联题
```
> 未来支撑：知识点图谱、能力迁移分析、本体化建模、前置知识树。
> ⚠️ 预留 schema 便宜，但**别现在就动手把整张图建出来**（无底洞）。MVP 阶段知识点仍是字符串；图结构作为「可选元数据层」叠加，老数据不动即可平滑升级。

## 落地优先级（当真正开始做时的建议顺序）
1. **A-3 Execution_Outcome** + **A-1 基础 Timeline**：数据已存在，最便宜，B 立刻能用。
2. **Struggle 信号补全**（见 06-v2）：随 B 一起，只影响推荐优先级、永不扣分。
3. 知识图谱 schema：E（自动出题）需要多用例 testcase 时，顺带把元数据层一起上。
4. Trace Snapshot 填充 / Error Embedding / 遗忘曲线 / 自适应难度：远期，按需。

> 一句话定位：**别把 A 当判题功能，把它当系统唯一可信的行为观测层。** 上面所有扩展都是在这层数据上长出来的。

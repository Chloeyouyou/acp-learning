# 09 · AI 协作调试空间（AI 共脑调试）

## 本文件的作用
定义五大模块里的「**独立 AI 共脑调试空间**」的设计与分阶段（B0→B1→B2）。**本轮只出设计，不写代码**。
前置：接着做已本地 commit；轻量登录仍待验收/commit。AI 共脑调试实现要等它们落定后再开，别叠未提交改动。

## 它是什么 —— 与 Bug 闯关的根本区别

| | Bug 闯关训练场（现有） | AI 共脑调试（本模块） |
|---|---|---|
| Bug 来源 | 系统**埋雷**，答案已知 | 预置样本 / 学生**自带代码**，答案系统**不一定知道** |
| 判对错 | `judge_fix` 真跑比对 `expected_output`/`fix_check` | **不做正式判题**，没有标准答案可比 |
| 驱动 | 六阶段状态机 + Ground Truth 硬门控 | 状态机硬门控**失效**，换轻量苏格拉底结对 |
| 完成 | 内化判定通过 | **学生点「解决了」（唯一门控）**；"报错消失"只是提示性观察，不当判据 |

**核心难点 = 系统不假装知道答案。** 唯一的 ground truth 只有两样：① 沙箱真运行的真实结果；② 学生自己说「我本来想要什么」。

> **完成判据为何只能是「学生确认」（重要，修正早期表述）**：单文件 bug 里最大的一类是**静默逻辑错**（如 off-by-one——干净运行、不抛异常，只是结果错）。对这类，「报错消失」要么恒真要么无定义，**不能当完成门控**，否则逻辑 bug 永远卡不到完成或被系统误判。所以 B0 完成的**唯一可靠信号 = 学生点「解决了」**；"报错消失"降级为给学生看的提示性观察。
>
> **推论：B0 必须主动问出「预期」**。逻辑 bug + 红线#7（无真实结果不准臆断）+ B0「不注入任何答案」三者叠加 → AI 拿到真实 `stdout=9` 也**没有任何依据**判断它对不对，除非学生先说出「我期望 10」。因此「**主动问出预期输出/预期行为**」必须写进 **B0** 的 coop 系统提示（不是留到 B1）。

> 顶部入口命名：**「AI 共脑调试」**；页面内部解释文案可用「结对调试」。

## 知返幻觉是地基级前提（务必沿用）

闯关有 `expected_output` 兜底，**这个模块什么都没有**——AI 一旦凭空编造运行结果，对零基础是重伤（见 [[acp-zhifan-no-sandbox-bug]]）。所以已修的两条在这里是**地基**，不是可选项：
- `tutor.py:234` 最高红线#7「绝不臆断运行结果」——没有真实运行结果就不准断言任何输出/通过与否。
- `run_result_note` / `inject_run_note`：学生每次点运行，真实 stdout/stderr 注入对话，AI 只能据此说话。

## 五个已拍板的设计决策

1. **自带代码范围**：B0 **不做**自带代码，只做**预置样本**；B1 再做自带代码，且**只支持单文件 Python**。
2. **成功标准**：**不做正式判题**；成功 = **学生点「解决了」（唯一门控）**；"报错消失"仅作提示性观察、不当判据（静默逻辑错不报错，见 §它是什么 的修正说明）。系统不假装知道标准答案。**逻辑 bug 下 AI 必须先问出学生的「预期」才能结对（B0 系统提示要求）。**
3. **画像/孪生**：B0 起记录 `ExecutionEvent(mode="coop")` 作事实日志；**B0/B1 不加能力分、不污染画像**；B2 再设计如何把 coop 信号喂给「AI 协作」能力维度。
4. **导师**：用**独立轻量导师**，**不复用**六阶段状态机；**可复用** 运行结果注入、红线#7、苏格拉底式引导；**不可复用** Ground Truth 硬门控（coop 不一定有标准答案）。
5. **入口**：顶部「AI 共脑调试」，内部解释用「结对调试」。

## 两个工程约束（本模块的关键，必须看清）

验证现有代码（`tutor.py` / `main.py`）后确认的硬约束——它们决定了 B0 和 B1 不是同一量级：

### 约束 1 · 现有 session/tutor 轨道硬依赖 `manifest["mines"][0]` 和 Ground Truth
- 系统提示内嵌 `[Ground Truth]`（root_cause / expected_fix / location），来自 `mine = session.manifest["mines"][0]`（`tutor.py:525-531`）。
- 阶段跃迁全靠对比已知答案：②定位要「与 Ground Truth 位置一致」（`tutor.py:216`）、③归因要「与 Ground Truth 根因语义一致才放行」（`tutor.py:186`）。
- `get_session`/`run_turn` 全程读 `session.manifest["mines"][0]`（`tutor.py:525/650/656/663/692`、`main.py:112/142`）。
- **推论**：**B0 可以复用 pattern/session 的存储形状**（样本 ≈ 伪 pattern，塞进 `mines[0]`），复用沙箱 `/run`、运行结果注入、会话存储；**但不能复用六阶段 `run_turn` 和 Ground Truth 硬门控**，必须走 **coop 专用轻量导师入口**。改动小，正是 B0「去风险」的价值。

### 约束 2 · 自带代码没有 pattern_id / mines[0]
- `pattern_id` 是 `TutorSession` 和 `ExecutionEvent` 的**必填字段**；`manifest["mines"][0]` 被多处直接读取。
- **自带代码没有雷、没有 pattern_id**，`manifest["mines"][0]` 会直接崩。
- **推论**：**B1 必须新增一种「无雷会话形状」**（manifest 不含 mines，或显式标记 coop 无雷）+ **pattern_id 可空 / 哨兵值（如 `"COOP"`）**。所以 **B1 不是 B0 的小增量，而是独立工程阶段**。

## 分阶段计划

### B0 · 预置样本（MVP，去风险）
**目的**：用精选样本把「结对调试」交互跑通，不碰「任意代码」的硬问题。
- 一组「协作样本」：以「帮我看看这段代码哪儿不对」的口吻给出有 bug 的程序（无埋雷压力、无六阶段、纯结对）。
- **复用**：沙箱 `/run` + 运行结果注入 + 会话存储；样本 ≈ 伪 pattern **复用存储形状**（约束 1）。
- **明确边界**：可复用 pattern/session 的**存储形状**，但**不能复用六阶段 `run_turn` 和 Ground Truth 硬门控**——B0 必须走 **coop 专用轻量导师入口**，与闯关导师逻辑隔离。即使样本系统知道答案，也按「只引导不给答案」走，且不用阶段硬门控。
- **导师**：独立轻量提示——苏格拉底引导 + 红线#7；不注入 Ground Truth、不做阶段跃迁。
- **完成**：学生 跑→观察→AI 引导→改→重跑→报错消失 + 学生确认。无正式判题。
- 落 `ExecutionEvent(mode="coop")`，先记不算分。

### B1 · 自带代码 + 结对导师 + fallback
- 学生**粘贴自己的单文件 Python** + 描述「问题是什么 / 我本来期望什么」。**AI 不生成代码**，只结对引导学生自己改。
- **新增无雷会话形状 + pattern_id 哨兵**（约束 2）——本阶段主要工程量。
- 结对导师基于真实沙箱运行引导；LLM 不可用时优雅降级（沿用现有降级）。
- 成功 = 报错消失 + 学生确认；无判题。
- 风控：输入大小上限、超时（沙箱仍 subprocess，可信内测够用；真隔离按 [[acp-roadmap-v1]] 留给公开前）。

### B2 · 扩展
- 多文件 / 长程序、更丰富上下文。
- 结对会话持久化 → 喂数字孪生（真实代码上的真实卡点，事件流金矿）。
- 设计如何把 coop 信号接入「AI 协作」能力维度（激活现在「未评估」的那一维）。
- 可选：从 coop 会话推断 thinking_pattern。

#### B2 第一步 · 协作信号埋点（**已实现**，2026-06-23，用户拍板「先记录不计分」）
难点：coop 无标准答案，任何"加分"都缺可信判定 → 易刷分、不诚实。且尚无任何 coop 真实数据。
**决策：先埋点、不进画像分。** 实现（`coop._log_collab_signal`）：会话 `resolve` 时，若学生**真动手运行验证过**（`runs>=1`），记一条 `ExecutionEvent(source="coop_resolve", kind="COLLAB", knowledge_points=[], meta.collab={runs,turns})`。
- **零画像影响**：纯 ExecutionEvent（append-only、绝不碰 capability_scores）；`knowledge_points=[]` 对掌握度隐形；`mode=coop` 被 timeline 过滤。
- **将来开分**：写个 calculator 读 `source="coop_resolve"` 事件按 collab 信号给「AI 协作」分即可，**一行开关**，事件流已攒好。
- 门槛 `runs>=1`：体现"不盲信 AI、动手验证"，是 AI_Verification 的诚实行为证据（非"解对了"）。
- 待真实使用数据后，再决定开分尺度（delta/防刷/上限）。回归测试 3 条（埋点/没运行不记/不进轨迹）。

## B0 实现细化（接口契约 / 数据形状 / 防污染）

> 在上面落地清单基础上，把接口、数据、复用点、防污染钉死到可直接实现。核对过现有代码（`main.py` run 端点、`tutor.run_result_note/inject_run_note`、`sandbox.run_code`、`event_engine.log_execution`、`timeline.build_timeline`）。

### 1. coop 样本数据形状（静态，类似 `question_training.SCENARIOS`）
新建 `services/coop.py`，内置一小组样本（不走埋雷引擎）：
```python
SAMPLES = {
  "off_by_one": {
    "title": "求和结果总是少一个",
    "ask": "我想把列表求和，但结果好像不对，你能帮我看看哪儿不对吗？",  # 学生口吻的首条求助
    "code": "def total(xs):\n    s = 0\n    for i in range(len(xs)-1):\n        s += xs[i]\n    return s\n\nprint(total([1,2,3,4]))",
    "kind": "logic",   # logic=静默逻辑错(不报错) / runtime=会抛异常；导师据此决定是否先问预期
  },
  # 再 2~3 个：None 解引用(runtime)、死循环(runtime/超时)、字典 KeyError(runtime) 等常见单文件 bug
}
```
- 样本**自带 buggy code**，无 `expected_output`/`fix_check`（不判题）。
- B0 样本系统其实"知道"哪错，但导师按「只引导不给答案」走，**不注入任何答案信息**。
- **`kind` 区分静默逻辑错 vs 运行时异常**：旗舰样本 off_by_one 是 `logic`——干净运行、打印 9（本该 10），**不报错**。导师对 `logic` 类样本**必须先问出学生预期**（见 §4），否则无从判对错。`kind` 仅用于导师提示策略，不做判题。

### 2. coop 会话形状（复用 `TutorSession` 存储，约束 1）
- 建 `TutorSession`：`pattern_id = "coop_<sample_id>"`（伪 id，B0 不碰 B1 的哨兵问题）、`manifest = {"mode": "coop", "sample_id": ...}`、`history` 预置首条学生求助（样本的 `ask`）。
- `manifest.mode="coop"` 是**绕开六阶段 + 防污染过滤**的唯一标记。

### 3. 接口契约（全部新建，`/api/coop/*`，与闯关端点隔离）
| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/coop/start` | `{student_id, sample_id?}` | `{session_id, sample_id, title, ask, code}` |
| GET | `/api/coop/{session_id}` | — | `{title, ask, code, messages, status}`（续做/刷新恢复） |
| POST | `/api/coop/{session_id}/run` | `{code}` | `{stdout, stderr, timed_out}` + 把运行结果注入对话 |
| POST | `/api/coop/{session_id}/message` | `{content}` | `{reply}`（coop 轻量导师回应） |
| POST | `/api/coop/{session_id}/resolve` | — | `{status:"completed"}`（学生点「解决了」） |

- **coop 专用 run**：**不能复用** `/sessions/{id}/run`——它调 `mine_engine.get_pattern(pattern_id)` 取 knowledge_points，对伪 pattern 会 `KeyError`。coop run 自己调 `sandbox.run_code` + `log_execution(mode="coop", knowledge_points=[])`，并复用 `run_result_note`/`inject_run_note` 注入。

### 4. coop 轻量导师（`coop.py` 内，不碰 `tutor.run_turn`）
- 复用 `tutor.client` + `TUTOR_MODEL`；自带一段 coop 系统提示：
  - 苏格拉底引导、**只引导不给答案 / 不写修改后的代码**；
  - **最高红线**：没有 `[真实运行结果]` 不准臆断输出/对错（沿用红线#7 精神）；
  - **不注入** Ground Truth、不提"标准答案"、不做阶段跃迁/判题；
  - **先问出预期（硬要求）**：若程序运行不报错但学生说"结果不对"（静默逻辑错），AI **必须先引导学生说出期望的输出/行为**，再据此结对——否则它拿到真实 `stdout` 也无从判对错（红线#7 + 不注入答案）。`kind="logic"` 的样本尤其如此。
- 输入：`history`（含注入的真实运行结果）+ 学生新消息 → 输出一段回应，append 进 history。
- LLM 不可用时优雅降级（给一句"先点运行看看真实报错，把它贴给我"之类，不崩）。

### 5. 防污染（关键，coop 版"双隐形"——面比初版更宽，已核实）
coop 会话是真 `TutorSession`，会被**任何按 TutorSession 扫描/计数的地方**捞到。必须逐处审：
- **成长轨迹**：`build_timeline` 选该生**全部** `TutorSession`（无 mode 过滤）→ coop 会混入（`line 221` 的 `try/except KeyError` 只防崩、不防混入，会出"空 pattern 退化 episode"）。**过滤加在 session 查询处（`line 192`）**：`mode=="coop"` 的会话直接排除——这样 `line 201` 的 executions 一并排除，一处搞定。加回归测试。
- **画像（按 kp 过滤的那维）**：coop `ExecutionEvent` 用 `knowledge_points=[]` → `profile.knowledge_mastery` 按 kp 成员过滤，天然隐形 ✓。
- **⚠️ 纯计数不受 kp 保护**：`profile.py:207` 捞该生**全部** ExecutionEvent；凡**不按 kp 过滤**的统计（总执行数、error_family 分布等）都会含 coop。审这些计数点，按 `mode`/`source` 排除。
- **TutorSession 计数/聚合面要全扫**：`/active-sessions`、`_cleanup_abandoned`、大厅/身份页的「已完成关卡数」「闯关战绩」等**凡对 TutorSession 数数/聚合处**，coop 的 `completed` 会灌进闯关战绩。**逐处按 `mode != "coop"` 过滤**，不止 timeline+profile。
- **不调 `emit()`、不动 `CapabilityScore`**（B0 不计分）。

### 5b. 伪 `pattern_id` 的脆弱性收敛（#3）
`get_pattern` = `load_patterns()[pattern_id]`，未知 id 直接 `KeyError`（无兜底）。`"coop_xxx"` 是注册表里的**非法 id**，任何**现在或将来** `get_pattern(session.pattern_id)` / `get_pattern(ev.pattern_id)` 而忘了先按 mode 过滤的调用点，都会让 coop 用户崩。**建议：给 `get_pattern` 对 `coop_` 前缀返回 `{}` 兜底**，把脆弱性收敛到一处（一次防御，胜过指望每个调用点都记得过滤）。

# 08 · 未完成关卡续做（接着做）

## 本文件的作用
把「续做未完成关卡」从当前的 **单会话静默自动恢复**，升级成 **大厅中可见、可选、可放弃的未完成关卡列表**。
后端能力已先行落地（`/active-sessions`、`/abandon`、收紧后的 `_cleanup_abandoned`，当前未提交），本文件定稿前端形态、交互、文案与连锁点。本轮实现前端 + 补测试 + 提交。

---

## 为什么要改（问题）

**现状机制**（`frontend/src/views/Arena.vue` `onMounted`，约 line 195）：
- 只靠 `localStorage('active_session')` 记 **一个** 会话；
- 进大厅时 **静默自动跳进** 上次那局（推一句「已恢复你上次未完成的关卡」）；
- 记不住多个、用户没得选、**没有「放弃」出口**。

**问题**：
1. 多会话场景下，静默自动跳让用户失去控制感——用户本想选新题 / 看复习 / 看成长轨迹，却被拽回上次那局，且**无法解释「为什么跳进这一局」**。
2. 后端已支持多会话（`/active-sessions` 取最近 5 个），单会话 localStorage 是瓶颈，**后端那份能力没被用起来**。
3. `localStorage` 与后端两份「续做真相」会打架。

---

## 核心决策（已拍板）

### D1 · 恢复方式 = 最近一局置顶高亮 + 其余默认折叠（不再静默自动跳）
- 进大厅 **不自动跳** 任何会话。
- **默认只展示最近活跃的一局**（置顶高亮，带「继续上次」主按钮 + 较弱的「放弃」入口）。
- 其余未完成关卡**默认折叠**，下方一行轻入口「还有 N 个未完成 · 展开查看」；点开才显示其余（每张可「继续」或「放弃」），展开后该行变「收起」。
- **展开状态只做当前页面态，不持久化**（刷新/退出回到默认只露一局）。
- **为什么默认折叠**：5 张卡全列会把「智能开一题 / 推荐」挤出首屏——万一用户不想接着做、只想开新题，得一路下滚很别扭。默认只露一局后，新题入口首屏即可见，不被未完成列表压住。
- 不选"全部压成单行"（信息太密）；不选"整块收起"（会损失"系统记得你"的感觉）。
- 理念：**系统记得你停在哪里，但不替你做决定，也不给你压迫感。**

### D2 · localStorage 单会话续做机制退役
- `localStorage('active_session')` 不再作为续做真相来源。
- 后端 `/active-sessions` 是唯一真相（server-side source of truth）。
- localStorage 至多保留为临时 UI 缓存（如"最近一局 id"用于置顶判断的兜底），**不再驱动自动恢复**。
- 不受影响、继续用 localStorage 的：`route.query.start`（变式跳转）、`intervention_seen`（开题小检查只弹一次）。

### D3 · 放弃 = 二次确认 + 安抚文案（强调不是删除）
- 点「放弃」弹轻确认，文案：
  > 放弃后不会删除你的学习记录，只是不再出现在「接着做」里。确认放弃吗？
  > 　[ 放弃 ]　[ 算了，继续做 ]
- 调 `POST /api/sessions/{id}/abandon` → 置 `status=abandoned`，**不删 history / 不删 ExecutionEvent**。
- 呼应「一句真实发言也是学习痕迹」：放弃 ≠ 抹掉，记录仍在成长轨迹可见。

### D4 · 文案走极简风，不叫"未完成会话"、不带 emoji
- 区块标题：**「接着做」**（备选：「半路留下的关卡」）。
- 每张卡副标题用阶段讲故事：**「上次停在：③ 归因」**，给「我做到哪了」的掌控感。
- 不暴露 session_id / status 等技术字段。
- 文档与实现 UI 文案统一不带 emoji。

## 大厅信息层级

「接着做」放在 Arena 选题大厅 **顶部**（智能推荐 / 浏览全部之上）。
与「今日复习」（在 Timeline 成长轨迹页）的关系：

| 入口 | 位置 | 角色 |
|---|---|---|
| 今日复习 | Timeline（成长轨迹） | 反思页里"系统邀请你回来"——间隔到期的老题 |
| 接着做 | Arena（选题大厅）顶部 | 行动页里"半截活儿，闭环它"——未完成的当前关卡 |
| 智能推荐 / 浏览全部 | Arena 大厅 | 开新题 |

自然优先级：**复习（最该做）→ 接着做（半截活儿）→ 新题**。
（「接着做」只在 Arena；不与 Timeline 复习卡争位，互补不重叠。）

### 大厅形态草图（默认折叠态）
```text
接着做
┌─────────────────────────────────────────┐
│ None 解引用             上次停在：⑤ 验证   │  ← 最近一局置顶高亮
│ 11 分钟前               继续上次 →   放弃  │
└─────────────────────────────────────────┘
还有 4 个未完成 · 展开查看        ← 轻入口，点开才显示其余

智能开一题 …                      ← 首屏即可见，不被压住
[ 智能推荐 ] [ 浏览全部题目 ]
```
点「展开查看」后，其余未完成关卡以普通卡片列出（继续 · 放弃），该行变「收起」。

## 后端（已写好，未提交，本轮一并提交）

`backend/app/main.py`：

- `GET /api/students/{student_id}/active-sessions`
  - 返回最近 5 个 `status=active` 会话摘要：`session_id / pattern_id / name / stage / mine_status / last_active_at`。
  - `last_active_at` = 该会话最新 `ExecutionEvent.timestamp`（无则 `created_at`），按之倒序——按真实活跃度排，置顶的就是列表第一个。
  - 纯只读，不写库。
- `POST /api/sessions/{session_id}/abandon`
  - `status: active → abandoned`，**不删 history / 不删事件流**。
- `_cleanup_abandoned` 收紧（严格定义，不放宽）：**四条全满足才删**——`active` + `mine_status=planted`（连雷都没定位）+ 零 `ExecutionEvent` + 零真实学生消息。**宁可漏清不可误删**，纯空壳才清；有任何真实运行 / 提交 / 发言一律保留。
  - 与续做列表自洽：纯空壳已被清，不会出现在「接着做」里（空壳没续做价值）。

## 前端改动（本轮实现）

1. `api.js`：加 `getActiveSessions()`、`abandonSession(id)`。
2. `Arena.vue`：
   - `onMounted` **删除 localStorage 静默自动恢复分支**（D2），改为拉 `getActiveSessions()` 填充大厅「接着做」区。
   - `route.query.start`（变式跳转）分支 **保留**，优先级仍最高。
   - 「接着做」区：第一张高亮 + 「继续上次」，其余普通卡 + 「继续 / 放弃」。
   - 点「继续」走现有恢复逻辑（`getSession` → 灌入 session 状态、`observationDone=true` 不重弹观察卡），从静默改为显式点击触发。
   - 点「放弃」→ 二次确认 → `abandonSession` → 从列表移除。
3. 样式复用大厅现有卡片风格 + 复习卡的视觉语言，保持一致；不带 emoji。

## 连锁点 / 待确认

- **Timeline 对 abandoned 会话的呈现**：`abandon` 不删事件流，被放弃的会话仍在 ExecutionEvent / timeline 里。需确认 `build_timeline` 对 `abandoned` 会话怎么算（是否成 episode）。**本轮先不改 timeline**，只记此连锁点。
  - **设计约束（重要）**：若未来 abandoned 会话进入 Timeline，措辞**不得带惩罚性**——用「曾停在这里」「中途放下」一类中性温柔表达，**禁用「失败」「半途而废」**。呼应产品基调：这是学习工具，不是考试。
- **测试覆盖**：`/active-sessions`、`/abandon`、收紧后的 `_cleanup_abandoned` 目前 **零测试**。本轮在 `backend/run_tests.py` 补：
  1. 空壳会话被清、有真实发言 / 运行的会话被保留；
  2. `active-sessions` 按 `last_active_at` 倒序、上限 5；
  3. `abandon` 置 abandoned 且 history / 事件流不丢。

## 不做（划界）
- 不改 `judge_fix` / 沙箱 / 六阶段状态机。
- 不改 timeline 派生逻辑（仅记连锁点）。
- 不引入新表（abandoned 复用现有 `status` 字段）。
- 不做"放弃后可一键恢复 / 回收站"（YAGNI；记录仍在事件流，真要找得回，但不做 UI）。

## 验收
1. 制造 2~3 个未完成会话（不同阶段 / 活跃时间）→ 进大厅「接着做」区按活跃度倒序列出、最近一局置顶高亮。
2. 点「继续上次」→ 正确恢复对话与阶段，不重弹观察卡。
3. 点某张普通卡「放弃」→ 弹确认 → 确认后从列表消失；该会话在成长轨迹 / admin 仍可见（history 未删）。
4. 进大厅 **不再** 静默自动跳任何会话。
5. 纯空壳会话（开了题没动）不出现在列表。
6. `run_tests.py` 全绿（含新增 3 类用例）。

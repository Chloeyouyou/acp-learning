# 12 · 提问训练（把「帮我看看」练成可协作的问题）

## 本文件的作用
定义「提问训练」从**前端写死的演示**演化为**真功能**的设计与分阶段（P0→P1→P2）。**本轮只出设计，不写代码。**
归属：五大模块里「AI 协作能力」训练的第一块；与 [[09-AI协作调试空间]]（共脑调试）并列，两者都喂同一个现在空着的「AI 协作」能力维度。
能力事件依据见 [[04-能力事件模型]] §4.9 `Prompt_Design`。

---

## 它是什么 —— 现状 vs 目标

| | 现在（demo） | 目标（真功能） |
|---|---|---|
| 提问内容 | 前端写死的 3 段台词，点「补一个要素」切换 | 学生写**自己的真实提问** |
| 诊断 | 写死的分数 / 三要素状态 | 知返用 **LLM 实时诊断**三要素 + 0~100 提问分 + 反馈 |
| 反馈 | 静态文案 | 针对学生这一版提问的具体建议 + 「再改一版」迭代 |
| 画像 | 无（且曾空许诺"+2"，已删） | P1 起落 `Prompt_Design` 能力事件，**点亮 AI协作维度** |

> 现在的 demo（`QuestionTraining.vue`，路由 `/question`）是 P0 的视觉与交互骨架，真功能在其上把"写死数据"换成"后端实时诊断"。

---

## 核心目标（不要跑偏）
**训练学生把「帮我看看 / 代码报错了」改写成一个 AI 真能接住的问题——即包含三要素：**
- **现象**：报了什么、看到什么（错误类型 / 实际表现）
- **上下文**：哪段代码、哪个文件、哪一行
- **预期**：你本来想要什么结果

这是一项**可迁移的协作素养**，不是某道题的答案。衡量它的货币就是 [[04-能力事件模型]] 的 `Prompt_Design`。

---

## 与能力事件 / 画像的关系（最大价值）
学生画像里 **AI协作能力现在是「未评估」**——系统从没产出过 `AI_Review / AI_Verification / Prompt_Design` 任一事件。
**提问训练是最快、最结构化的喂料口**：它直接产 `Prompt_Design`（`llm_judge`，归 AI协作维度，权重 0.30），一旦接入，画像里那根灰轴就活了。
落事件的唯一入口已存在：`event_engine.emit(...)`，`Prompt_Design` 已在注册表与 LLM 白名单内。

## 分阶段

| 阶段 | 做什么 | 接画像？ | 前置 |
|---|---|---|---|
| **P0（MVP）** | 几个**预置场景** + 学生写真实提问 → 后端 LLM 诊断三要素(各有无) + 0~100分 + 具体反馈 + 「再改一版」迭代 | ❌ **不记分、不动画像** | 文档定稿 |
| **P1-lite（资产化）** | 每次诊断**沉淀为事件流资产**（复用 `ExecutionEvent`）：可回放、可统计"最近最常漏哪个要素"；据此做短板个性化反馈 | ❌ **仍不记分、不动画像** | 判定质量已验（93%/98%，达标） |
| **P1-full（画像计分）** | 真正 `emit(Prompt_Design)`：三要素全→+2 / 2项→+1；"一贴帮我看看"→-1。**点亮 AI协作维度** + 防刷 | ✅ | **用户验收 P1-lite 资产 + 判定质量后明确开启** |
| **P2-A** | 学生**自带真实问题**（`scenario_id="custom"`，自由描述背景+提问）→ 复用现有诊断/资产化/计分/短板 | ✅（复用 P1-full） | P1-full 稳定 |
| **P2-B（暂缓）** | 闯关对话里**旁路**给提问打分（[[04-能力事件模型]] §4.9 另一触发点）——**先不实现**，仅记为未来项 | — | 见 §P2-B 暂缓 |

**纪律（与 B0 一致的"先记不算分"）**：LLM 判三要素若判不准会**污染画像**。所以——
- **P0**：只诊断与反馈，**完全不持久化**。
- **P1-lite**：把诊断**沉淀成数字资产**（事件流），可回放/统计/做个性化，但**结构上就不进画像分数**（用 `ExecutionEvent` 这条"只记事实不计分"的轨道）。
- **P1-full**：确认资产与判定都稳后，才真正 `emit(Prompt_Design)` 让 AI协作维度加分。

## P0 详细设计

### 场景（预置）
一小组「学生会真的遇到」的场景，每个给一句背景，让学生据此写提问。例如：
- 登录功能跑不通（demo 现用的这个）
- 列表页数据读不出来 / 一直空白
- 函数返回结果不对（算出来的数和预期对不上）

每个场景配一对**差/好对照**（保留 demo 已有的对照卡）。

### 诊断（后端 LLM）
- 新端点：`POST /question-training/diagnose`，入参 `{scenario_id, prompt}`。
- LLM 判定并返回：
  ```json
  {
    "phenomenon": true,        // 现象是否说清
    "context": false,          // 上下文是否说清
    "expectation": false,      // 预期是否说清
    "score": 52,               // 0~100 提问分
    "feedback": "现象说清了；再告诉 AI 错在哪个文件/第几行，它就能精准定位。",
    "confidence": 0.86
  }
  ```
- **复用防幻觉地基**（见 [[acp-zhifan-no-sandbox-bug]]）：这里不跑代码，但导师提示同样禁止臆断"运行结果/正确答案"；只评估**提问本身**的三要素完整度，不替学生回答技术问题。
- **三要素 → 分** 对齐 [[04-能力事件模型]] §4.9：3 项全→高分段、2 项→中、≤1→低。具体分值映射 P0 先给经验值，P1 与 delta 规则对齐。

### 反馈与迭代
- 诊断后高亮**缺哪个要素**、给一句**怎么补**的具体建议。
- 「再改一版」：学生改写后重新诊断，看分数/三要素变化（进步可视）。

### 前端
在现有 `QuestionTraining.vue` 上改：
- 选场景 → **真实输入框**（替换写死台词）→ 提交 → 知返实时诊断（替换写死数据）→ 「再改一版」。
- 保留：差/好对照卡、提问分进度条、三要素 ○/✓、知返点评区。

### P0 明确不做
- 不落任何能力事件、不动画像、不算分。
- 不让 AI 替学生写技术答案（这是**提问**训练，不是问答）。
- 不接闯关对话旁路（属 P2-B，已暂缓）。
- **不持久化**：提问历史只活在前端本次会话内（刷新即没）。"总结短板/个性化"需要跨会话数据，属 P1。

## P1-lite · 资产化（沉淀进事件流，不计分）

> 目标：把每次提问诊断**变成可回放、可统计的数字资产**，但**绝不影响能力画像分数**。这是"先把数据 mapping 进库"的最稳一步——拿到资产、验证闭环，再决定是否 P1-full 加分。

### 用哪条轨道：复用 `ExecutionEvent`（不新建表、结构上就不计分）
系统里 `Event` 与 `ExecutionEvent` 是两条轨道：
- `Event` → `event_engine.emit()` → **会调 `profile.apply_event()` 进画像**（confidence≥阈值时）。复用它必然碰画像，P1-lite 不走。
- `ExecutionEvent` → `event_engine.log_execution()` → **只 INSERT、永不调 apply_event**（模型注释即"绝不影响 capability_scores"）。**这正是 P1-lite 要的"记录事实不计分"轨道**——复用它，零新表、结构上就不可能污染画像。

### 怎么存（命名空间隔离，确保对画像/轨迹双隐形）
新增一个轻量写入（如 `question_training.log_diagnosis(...)` 包一层 `log_execution`），每次诊断写一条 `ExecutionEvent`：

| 字段 | 值 | 为什么 |
|---|---|---|
| `source` | `"qt_diagnose"` | 独立来源；timeline 只认 `run`/`submit`，自动忽略 |
| `session_id` | 提问训练合成 id（**不建 TutorSession**） | timeline 按 `session_id ∈ TutorSession` 过滤 → 对成长轨迹隐形 |
| `pattern_id` | 哨兵 `"QUESTION_TRAINING"` | 提问训练无 pattern；仅占位，不被聚合按此分组 |
| `knowledge_points` | `[]` | profile 掌握度按 kp 成员过滤 → **空 kp = 对画像完全隐形** |
| `kind` | `"QT"` | 非 RE/WA/HANG/OK，不进任何对错统计 |
| `meta` | 见下 | 真正的资产载荷 |

**`meta` 载荷（回放与统计的全部依据）**：
```json
{
  "mode": "question_training",
  "scenario_id": "login",
  "prompt": "学生提问原文",
  "phenomenon": true, "context": true, "expectation": false,
  "score": 66,
  "feedback_summary": "现象+上下文已清，缺预期",
  "confidence": 0.9,
  "degraded": false
}
```

### 双隐形保证（实现时必须回归验证）
- **画像**：`profile.py` 按 `knowledge_points` 成员过滤执行事件；空 kp → 不计入任何知识点的 evidence/struggle。✅
- **成长轨迹**：`timeline.py` 按 `session_id ∈ 本人 TutorSession` 且 `source∈{run,submit}` 过滤；合成 session + `qt_diagnose` 源 → 不进时间线。✅
- 实现后跑 `run_tests.py` + 手测画像/轨迹，确认提问训练事件**不出现**在两处。

### 回放与短板统计（喂给个性化）
- 统计"最近最常漏的要素"：查本人 `ExecutionEvent`（`source="qt_diagnose"`），读 `meta` 数三要素各自 false 的次数。
- **degraded / `confidence<0.7` 的事件：记录事实，但不参与短板统计**（沿用画像同款过滤口径）。

### P1-lite 明确不做
- 不调 `event_engine.emit`、不落 `Prompt_Design`、不动 `CapabilityScore`/画像分。
- 不建新表、不动 Profile 画像加分逻辑、不动 B0 共脑调试、不动六阶段。
- 不做 Postgres（VPS 上 SQLite 即持久资产；上线/真人前再议）。

## P1（个性化）· 提问短板总结 → 个性化反馈

> 复用闯关里已验证的同款机制：成长轨迹的「**你常见的思维默认值**」（`timeline.py` 跨题聚合反复犯的同类错）+ 开题时的个性化提醒（`intervention_for`）。提问训练做一个平行版：跨多次提问统计「**你最常漏哪个要素**」，让知返的反馈/提示**针对你的弱项**说话。

### 数据从哪来（依赖 P1-lite 的资产化）
- 短板统计**跑在 P1-lite 沉淀的 `ExecutionEvent`（`source="qt_diagnose"`）上**——`meta` 里已存三要素结果、scenario、prompt。
- **无需新表、也不依赖画像加分**：直接回放本人这些事实事件，统计"最近 N 次里每个要素的缺失频次"。事件流本就是 append-only 的事实源（[[04-能力事件模型]] §5.1）。
- 所以"短板个性化"在 **P1-lite 就能做**（纯资产驱动），不必等 P1-full 加分。

### 怎么总结（轻量聚合，不引入新判定）
- 取该学生最近 N 次提问事件，数三要素各自被判 false 的次数。
- 选出**最常漏的 1 个要素**（如"预期：6/8 次没写"）作为"短板"；够样本量才给（如 ≥3 次提问），否则不显示——避免一两次就贴标签（对齐思维默认值的 `enough` 门槛）。

### 怎么个性化（喂给知返 + 前端提示）
- **文案纪律：不贴死标签。** 一律用"最近几次里，xxx 相对少一些"这类**观察式、非评判**措辞，**禁止**"你总是漏 xxx""你不会写 xxx"这类定性。对齐成长轨迹「镜子非审判」的口吻。
- **诊断反馈**：在 `diagnose` 的 system 提示里带上该学生的短板**作为软提示**（如"该学生最近几次里【预期】相对少一些，可在反馈里轻轻提醒"），让 feedback 更有的放矢，但仍只评本次提问。
- **输入框占位/开场**：进提问训练时若有短板，给一句观察式提醒（"最近几次你的【预期】写得相对少，这次可以先想想想要什么结果"）——平行于 `intervention_for`。
- **成长轨迹**：可选——把"提问短板"作为一条，融进现有「思维默认值」区或单列，同样用观察式措辞。

### P1 个性化的边界（遵守灵犀宪章 [[11-灵犀感知层-Presence-Layer]] §全系统个性化宪章）
提问短板总结是灵犀宪章下的一个**触点**，统一遵守那里的口吻 / 总量预算 / 闸门，本节只列本触点的特化约束：
1. **只总结最常漏的要素**：单一短板，不做复杂画像。
2. **够样本量才显示**：达不到门槛（如 <3 次提问）完全不显示（宪章·闸门）。
3. **只影响反馈措辞，不额外加扣分**：短板仅用于提醒与语气，**绝不改变** `Prompt_Design` 的加/扣分规则（加扣分仍只走 [[04-能力事件模型]] §4.9 的 delta）。
4. **文案不贴标签**：用"最近几次里，xxx 相对少一些"，不写"你总是漏 xxx"（宪章·口吻）。
5. **不突破全局总量预算**：与大厅灵犀、开题 intervention 等共用"同页/同次访问最多一句"的预算，按优先级让位，不叠加轰炸（宪章·总量预算）。
6. **统计来源（按阶段）**：**P1-lite** 阶段统计来源是 `ExecutionEvent(source="qt_diagnose")`（读 `meta` 三要素）；**P1-full** 之后才可改用 / 合并 `Prompt_Design` 事件。两者不混用。均要求 `confidence≥0.7`、不引外部数据（宪章·闸门）。

## P2-A · 自带真实问题

> 把提问训练从预置场景延伸到**学生自己正遇到的真实问题**——训练目标不变（只练提问质量、不替学生解题）。是 P1 的最小延伸：诊断/资产化/计分/短板**全部复用**，几乎不新增后端逻辑。

### 做什么
- 在现有 3 个预置场景旁加一个**「我自己的问题」**入口（`scenario_id="custom"`）。
- 学生在一个输入框里**自由描述背景 + 提问**（不再有系统给定的场景背景）。
- 提交 → 走**同一个** `diagnose`（判三要素+分+反馈）→ 同一套资产化（`log_diagnosis`）+ 计分（`score_diagnosis`）+ 短板（`weakness_summary`）。

### 复用 / 改动
- **后端**：`diagnose` 本就是纯文本判三要素、不依赖预置场景，`scenario_id="custom"` 时只需在 LLM 提示里把"场景背景"换成"学生自带、无预设背景，只就这段文字判三要素"。`SCENARIOS` 加一个 `custom` 占位（title=「我自己的问题」、brief 为空或引导语）。
- **前端**：场景选择多一个「我自己的问题」；选中时**不显示**预置 brief，输入框引导语改为"先讲清你的情况，再写你想问 AI 的问题"。其余（诊断卡、历史回退、短板提醒）不变。
- 资产 `meta.scenario_id="custom"`，与预置场景**同表共存**，短板统计天然合并（都按本人 `qt_diagnose` 回放）。

### 边界（务必保留）
- 仍**只训练提问质量**，不替学生解决技术问题、不臆断运行结果/答案。
- **复用** P1-full 全部防刷：同句去重、日上限 +6、C 档泛泛求代办降档、低置信不进画像、degraded 不记。
- **不动**六阶段、不动 B0、不动闯关旁路（P2-B）。
- custom 提问可能更长/更杂，诊断提示仍只输出三要素布尔+反馈，不展开解题。

## P2-B（暂缓）· 闯关对话旁路打分

> 记为**未来项，本阶段不实现**，也**不与 P2-A 绑定**。

设想：在 Bug 闯关对话里，后台顺便给学生提问质量打 `Prompt_Design` 分（[[04-能力事件模型]] §4.9 的"导师 AI 旁路评估"触发点）。

**暂缓原因**：
1. 闯关里很多学生消息**不是提问**，而是回答知返的苏格拉底追问、陈述观察/猜测——盲目旁路打分会**污染 `Prompt_Design`**。
2. 需要先设计一个**「这条消息是不是求助提问」的判别器**（又一次 LLM 判断），只对真正"在问知返"的消息打分。
3. 会**增加闯关的 LLM 成本**（每条消息多一次判别+诊断）。
4. 必须是**纯 side-channel**：`run_turn` 照跑、绝不干扰六阶段。

**前置（想清楚再做）**：先定义"闯关里哪条算提问"，再设计判别器与防污染；与 P2-A、B0 解耦，单独立项。

## 防刷 + 防污染画像

| 关注 | P0 | P1-lite（资产化） | P1-full（计分） |
|---|---|---|---|
| 污染画像 | **完全不记分**（纯展示、不持久化） | **结构上不进画像**（走 `ExecutionEvent`，永不调 apply_event；kp=[] 对画像隐形） | 仅在用户验收资产闭环+判定质量后开启 |
| 刷分 | 不涉及 | **不涉及**（不计分，刷不出分） | **日上限**：`Prompt_Design` 每日正向 delta 合计封顶（对齐 [[04-能力事件模型]] §5.5 的 +6）；**会话上限**：单次训练会话最多记 N 次正向事件 |
| 低质判定 | — | `confidence<0.7` / `degraded` 记录事实，但**不参与短板统计** | `confidence<0.7` 入库但不参与画像（沿用 `event_engine` 现有规则） |
| 证据 / 载荷 | — | `ExecutionEvent.meta` 存 scenario/prompt/三要素/score/feedback_summary/confidence/degraded，供回放与短板统计 | `evidence.summary`=三要素拆解结论、`refs` 含提问原文，供画像回放/复核 |

> **session_id**：P1-lite 用**合成 id**（不建 TutorSession），仅作分组标识、不进 emit；P1-full 若 `emit` 需要 session，沿用同一合成 id 体系，细节 P1-full 设计时定。

## 拍板的决策（已确认）
1. **P1 拆 lite / full**：先 **P1-lite**（诊断资产化进事件流、可回放可统计，**不计分**）；确认资产与判定都稳后，再 **P1-full**（`emit(Prompt_Design)` 接画像加分）。
2. **资产化轨道**：P1-lite 复用 `ExecutionEvent`（只记事实不计分），命名空间隔离对画像/轨迹双隐形；**不新建表、不动 Profile 加分逻辑**。
3. **定位**：独立训练模块，不在闯关里强插；闯关对话旁路打分属 P2-B（已暂缓）。
4. **角色**：知返只**诊断提问**、不替学生答技术问题。

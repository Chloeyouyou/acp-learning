# AI协同编程学习系统（ACP Learning）V0.1

> 概念方案 · 2026-06
> 定位：不是 OJ 需求文档，而是一个全新的产品定义。

---

## 1. 项目定位

### 1.1 项目背景

当前编程教学主要采用「课程讲授 + 编程练习 + 在线判题（OJ）」模式，学生通常通过大量刷题巩固知识。然而现有平台普遍存在三个问题：

#### 问题1：结果导向

系统只返回 `AC / WA / TLE / CE / RE`。学生知道**错了**，但不知道**为什么错**。

#### 问题2：AI成为答案生成器

学生当前普遍使用 ChatGPT、Claude、Gemini 解决编程问题，典型流程：

```text
报错 → 复制给AI → 获得答案 → 复制回项目
```

虽然 Bug 被解决，但能力没有成长。

#### 问题3：缺乏能力建模

当前系统关注「题目通过率」，而非「学生能力成长」。系统无法回答：

- 学生真正掌握了什么？
- 经常出现什么错误？
- 哪些能力薄弱？
- 应该如何学习？

---

## 2. 产品目标

本系统不以「判题」为核心，而以 **AI协同学习** 为核心。

目标是让学生在与 AI 共脑过程中：

- 学会编程
- 学会调试
- 学会提问
- 学会使用 AI（学会 Vibe Coding，而不是被 Vibe Coding 替代）

最终形成 **学生 × AI** 协同解决问题的能力。

---

## 3. 核心理念

**传统模式：**

```text
学生 → 写代码 → 提交 → 结果
```

**本系统模式：**

```text
学生 → 发现问题 → 与AI协作 → 定位问题 → 分析原因 → 修复问题 → 知识沉淀 → 能力成长
```

### 3.1 核心教学闭环：埋雷 → 共脑 → 内化

系统的核心教学手段是一个三阶段闭环：

```text
阶段1：埋雷
系统在练习/项目代码中有意埋下Bug（按知识点与难度设计）

阶段2：AI共脑解决
学生发现异常 → 与AI导师协作定位 → 引导式修复（AI不直接给答案）

阶段3：理解内化
AI反向提问（"为什么这里会越界？"）
→ 学生用自己的话复述原因
→ 变式练习（同类Bug换场景再现）
→ 沉淀为错题知识卡 + 能力画像更新
```

**关键设计**：解决 Bug 不是终点。只有学生能解释「为什么错、怎么发现、如何避免」，并通过变式验证，该知识点才算内化完成。

## 4. 系统角色

| 角色 | 职责 |
|------|------|
| 学生 | 学习主体 |
| AI导师 | 引导式教学（不直接给答案） |
| 教师 | 课程设计与监督 |
| 埋雷引擎 | 按教学目标在代码中生成/植入Bug |
| 能力画像引擎 | 持续追踪成长 |

---

## 5. 核心模块

### 模块1：AI共脑调试空间

学生提交代码后，AI **不直接给答案**，而采用「提示 → 追问 → 引导 → 验证」方式帮助学生解决问题。

**示例**：学生代码出现数组越界：

```java
for(int i=0;i<=arr.length;i++)
```

AI 回应：

```text
我发现问题可能与循环边界有关。你认为：
A. i初始化错误
B. 循环条件错误
C. 数组声明错误
```

学生选择后继续引导。**目标：训练 Debug 能力，而非复制答案。**

### 模块2：Bug闯关训练场（埋雷训练）

系统通过 **埋雷引擎** 提供 Bug 题库与带雷项目，覆盖真实问题：数组越界、空指针、死循环、递归错误、SQL错误、API错误等。

每一关执行完整的「埋雷 → 共脑 → 内化」闭环：

```text
进入带雷代码/项目
↓
发现Bug（运行、读日志、写测试）
↓
与AI共脑分析定位
↓
修复Bug
↓
内化环节：
  · AI反向提问，学生解释成因
  · 变式题再现同类Bug
  · 生成个人错题知识卡
```

**目标：培养工程调试能力，并确保"修好了"升级为"学会了"。**

### 模块3：Vibe Coding训练场

训练学生**正确的 Vibe Coding 方式**——不是「一句话让AI生成全部代码」，而是学会与 AI 协作完成从需求到实现的全过程。

学生提出需求（如「做一个图书管理系统」），AI 不直接生成代码，而是引导：

- 需要哪些实体？
- 实体关系是什么？
- 数据库如何设计？
- 接口如何设计？

**与埋雷机制结合**：在 AI 协助生成的代码中，系统可有意保留教学性 Bug 或不完善设计，要求学生审查、发现并与 AI 共脑修复——训练「不盲信 AI 输出、会验证 AI 代码」的关键习惯。修复后进入内化环节，让学生说清 AI 代码错在哪、为什么。

**目标：培养需求分析、系统设计、AI协作、AI代码审查能力。**

### 模块4：AI提问能力训练

训练学生「如何向 AI 提问」。系统比较：

**Prompt A（差）：**

```text
代码报错了
```

**Prompt B（好）：**

```text
Java项目出现NullPointerException
错误发生在UserService第32行
预期行为是完成登录
```

AI 从「问题描述完整度、上下文完整度、定位效率」三个维度评估。

**目标：培养 AI 时代核心能力。**

### 模块5：能力画像系统

系统不记录「做过多少题」，而记录「掌握了什么能力」。

**能力维度：**

| 维度 | 子项 |
|------|------|
| 编程能力 | 数组、链表、树、图、动态规划 |
| 工程能力 | Debug、日志分析、API调用、数据库 |
| AI协作能力 | Prompt设计、问题拆解、AI验证、AI代码审查 |
| 系统设计能力 | 建模、架构设计、模块划分 |

画像区分两层状态：**已解决**（在AI帮助下修复过）与 **已内化**（能独立解释成因并通过变式验证）。

---

## 6. 能力成长引擎

每次学习行为（代码、对话、Bug、修复过程、内化复述）都会生成 **能力事件**。

例如：

```text
成功定位空指针          → Debug能力 +2
独立解释越界成因并通过变式 → 边界意识 +3（标记为已内化）
连续5次边界错误          → 边界意识 -3
全程依赖AI提示完成修复    → 该知识点保持"已解决未内化"状态
```

最终形成 **动态能力画像**。

---

## 7. 创新点

1. **从「AI替学生编程」变为「AI教学生与AI协作编程」**
2. **从「结果导向」变为「过程导向」**
3. **从「刷题平台」变为「能力成长平台」**
4. **「埋雷 → 共脑 → 内化」教学闭环**：有意制造问题，先协作解决，再验证内化
5. **建立「代码 → 错误 → 知识点 → 能力 → 画像」能力建模体系**

## 8. 未来扩展方向

本系统与本体、能力建模、学习进化方向天然连通，后续可扩展为：

```text
知识点本体 → 错误模式本体 → 能力本体 → 学生数字孪生
```

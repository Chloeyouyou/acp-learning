# CI、端到端测试与知返回复质量守门计划（2026-07-15）

## 目标

在现有 119 项确定性测试、过程回放和教学策略留痕之上，再补三道保险：

1. 知返生成回复后必须经过确定性质量守门，不再只相信 prompt 自觉；
2. 用浏览器真实走通学生身份、运行/提交、回放、教师钻取关键链路；
3. 每次 push / pull request 自动执行后端、迁移、前端构建和浏览器冒烟测试。

## 约束

- 质量守门只检查明确可判定的红线，不用另一个 LLM 给 LLM 打分。
- 不改变六阶段跃迁规则；守门只控制交付给学生的 `reply`。
- 失败关闭：首次回复不合格时带原因重试一次；再次失败则换成阶段安全兜底问题，不把违规内容交给学生。
- 守门结果写入现有 `session_messages.meta`，不增加新表。
- E2E 不调用真实 DeepSeek，不消耗线上 key；调试动作走本地 subprocess，CI 环境只运行仓库固定题目。
- 浏览器测试使用 Chromium 单浏览器冒烟档，控制运行时间；跨浏览器矩阵留以后。

## M1 · 回复质量守门

### 确定性检查

- `direct_fix_leak`：回复包含题目 `expected_fix` 的规范化文本；
- `question_count`：结尾问题不是恰好一个，防止一次塞多个核心任务；
- `route_not_observable`：策略要求换路，但回复没有出现相应可观察结构：
  - analogy：像 / 好比 / 想象；
  - micro_example：比如 / 例如 / 假设；
  - execution_trace：先 / 然后 / 最后 / 入口 / 返回；
  - contrast：对比 / 区别 / 如果…而…。

### 执行路径

```text
LLM 结构化输出
  → schema 校验
  → reply 质量守门
    → 通过：正常交付
    → 不通过：把违规代码作为系统纠错信息重试一次
      → 通过：交付重试结果
      → 仍失败：使用当前阶段的安全小问题兜底
```

### 可观测字段

```json
{
  "reply_guard": {
    "passed": true,
    "attempts": 2,
    "fallback_used": false,
    "violations": ["question_count"]
  }
}
```

验收：泄露 `expected_fix`、连续两个问题、换路未落实都能拦截；第二次仍违规时学生只能收到安全兜底回复。

## M2 · 端到端冒烟

新增 Playwright Chromium 测试：

1. 身份页输入学号并进入，确认 token 身份真正生效；
2. API 建会话 → 运行带雷代码 → 提交正确代码；
3. 学生回放页看到关键突破和动作证据；
4. 教师用 Bearer 管理口令看到该学生、钻取并进入同一会话回放。

测试使用临时 SQLite 数据库；不会读写开发数据库。

验收：本机/CI 运行 `npm run e2e` 通过；失败时保留 Playwright trace 供定位。

## M3 · GitHub Actions

触发：push 到 `main`、`feat/**`，以及针对 `main` 的 pull request。

流水线：

1. Python 3.12 安装锁定依赖；
2. 后端全量 `run_tests.py`；
3. 临时库 `alembic upgrade head` + `alembic check`；
4. Node 安装 `package-lock.json` 锁定依赖；
5. 前端 production build；
6. 安装 Chromium 并运行 Playwright E2E；
7. 失败时上传 trace/report。

验收：workflow YAML 可解析，所有命令与本地验证入口一致，CI 不需要真实密钥。

## 回滚边界

- 守门函数是纯函数，可单独关闭重试而保留检测/记录。
- Playwright 与 workflow 不进入运行时依赖。
- E2E 临时数据库和构建产物均不提交。

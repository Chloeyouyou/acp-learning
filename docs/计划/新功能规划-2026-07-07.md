# ACP 新功能方向规划（2026-07-07）

> 背景：v2 两周计划（还债 + 过程化 + 课程 + 教师端）已完成。但那是"把既定计划做完"，
> 不等于"产品做完"。这份文档把四个真正的新功能方向各自铺开成可评审的计划，供拍板选做。
> 原则：每个方向都接现有架构（事件流四表不动、皇冠资产 tutor.py 谨慎动），先出计划再动手。

四个方向（按"和现有资产的复用度 / 见效速度"排序）：
- **方向一：让过程数据活起来**（复用度最高，最快见效——数据都建好了，只差"用"）
- **方向二：情感/陪伴层**（把 LingXi 的长处移植进 ACP）
- **方向三：Vibe Coding 训练场**（设计文档里未做的整块新玩法）
- **方向四：画像/推荐智能化**（最"深"，为长期"懂每个学生"打底）

---

## 方向一 · 让过程数据「活起来」

### 痛点
M2/M3 把代码快照、消息时间线、回放都建好了，但这些数据**只是"能看"，还没"会用"**——
没反哺给导师引导、没主动照给学生。金矿挖出来了，还堆在仓库里。

### 做什么（三个子功能，可独立上）

**1.1 导师看得见历史模式（喂跨局信号给状态机）**
- 现状：导师只看当前这局。④失败已能喂"这次改动 vs 雷行"（M2 做了）。
- 升级：让导师能引用**跨局/跨题**的快照模式。例：
  - "同一道题你第 3 次卡在②定位了" → 导师换更具体的切入。
  - "你这三道边界题，都是先盲改再定向" → 呼应成长轨迹的思维默认值。
- 接法：新增 `process.recent_struggle_signal(db, student_id, pattern_id)` 纯派生，
  读 code_snapshots + execution_events 算"重复卡点"，像 diff_summary 一样拼进 system prompt 旁白。
- 红线：仍是旁白、导师不照念；只增引导精度，不改六阶段门控。

**1.2 回放页自动标注"关键转折点"**
- 现状：回放是平铺的时间线，学生自己看。
- 升级：自动标出**"想通的那一步"**——从"连续报错/盲改"到"改对雷行/通过"的跃迁点，
  打一个"💡 这里你想通了"的标记；从 planted→found→fixed 的阶段跃迁也标。
- 接法：`build_replay` 已有全部数据，只在派生层加"标注"字段，前端加高亮。纯只读。
- 价值：把回放从"流水账"变成"你的成长故事"，也是最好的 demo 素材。

**1.3 "我的调试足迹"周报（派生聚合）**
- 一句话给学生看：这周做了几题、最常卡在哪个阶段、思维默认值有没有松动、
  哪道题从"盲改"进步到"定向改"。纯派生，复用 timeline + code_snapshots。

### MVP 与工作量
- MVP = 1.2（回放自动标注转折点）——最快、最惊艳、纯派生零风险。约半天。
- 1.1 约 1 天（要设计"重复卡点"的判定 + prompt 注入，谨慎测导师不被带偏）。
- 1.3 约半天。
### 风险
- 1.1 动 prompt，要防"旁白污染导师语气"——用 M1 的 stub-LLM 测法守。
- 其余纯派生只读，零风险。
### 依赖
- 无。数据都在。**这是四个方向里最该先做的**——投入小、复用现成数据、直接提升体验。

## 方向二 · 情感/陪伴层（把 LingXi 的长处给 ACP）

### 痛点
ACP 的灵犀感知层只做了"大厅招呼 + 挫败气泡"。而 LingXi 里那套细腻的东西——
压力累积、恰到好处的主动干预、连续低压力就平稳退开——ACP 学习场景完全用得上，
现在几乎空白。学生卡到崩溃时，ACP 只有导师一个"讲题"的声音，没有"我懂你难受"的声音。

### 做什么

**2.1 学习挫败的"压力感知"（移植 LingXi 的累积-干预模型）**
- LingXi：每条 AI 回复带 `[STRESS:X]`，累积到阈值弹干预卡、连续 3 条低压力退出。
- ACP 版：信号源换成**学习场景的客观事实**（不猜情绪）——连续 N 次同类报错、
  同阶段停留轮数、求助措辞、放弃倾向。累积到阈值 → 导师切"扶一把"模式升级 +
  可选弹一张"要不要歇会/换道简单的"卡片。
- 现有基础：tutor.py 已有 `detect_frustration` + 止损共情层 + 灵犀气泡（门槛=连续3次真挣扎）。
  这是把"单轮检测"升级成"累积-干预-平稳退出"的完整曲线。

**2.2 成就时刻的正向回应（LingXi 的流星雨之于 ACP）**
- LingXi 有愿望罐/流星雨这种"情绪出口"。ACP 现在内化通过只有一句文字。
- 升级：首次内化、迁移验证成功、连续攻克同类题——给一个克制但真诚的高光时刻
  （不是廉价的撒花，是"你把学到的道理用到新题上了"这种被看见的确认）。

### MVP 与工作量
- MVP = 2.1 的"累积曲线"（把现有单轮气泡升级成累积-退出），约 1-1.5 天。
- 2.2 约半天。
### 风险
- **最高红线（你在 LingXi 反复守的）：克制、不打扰、不越界、不煽情。** 干预太频/太假会毁体验。
  必须像 LingXi 那样"攒够信号才碰、说三句就退"。这方向成败全在分寸，不在技术。
- 动 tutor.py 的止损层，要谨慎测。
### 依赖
- 无强依赖，但建议在方向一之后——先让"过程数据活起来"，情感层能读到更丰富的信号。

## 方向三 · Vibe Coding 训练场（未做的整块新玩法）

### 痛点
产品概念 5 大模块里，**模块3 Vibe Coding 训练场整个没做**。现在 ACP 只训练"调试
别人/自己写的 Bug"，但 AI 时代更核心的是"**会用 AI 从需求到实现、且不盲信 AI 代码**"。
这是产品定位（"学会 Vibe Coding 而非被 Vibe Coding 替代"）的另一半。

### 做什么（原始构想 + 落地设计）
- 学生提需求（"做一个图书管理系统"）→ AI **不直接写代码**，而是引导需求分析：
  要哪些实体？关系是什么？数据库怎么设计？接口怎么设计？（像调试导师一样"不给答案、引导想清"）
- **与埋雷结合**：AI 协助生成的代码里**有意留教学性 Bug/坏设计**，要学生审查、发现、
  共脑修复 → 训练"不盲信 AI 输出、会验证 AI 代码"。修完进内化：说清 AI 代码错在哪。
- 复用：埋雷/六阶段/事件/画像全套能复用；新增的是"需求→设计"的前半段引导状态机。
- 新能力维度：需求分析、系统设计、AI 代码审查（registry 已预留 `AI_Review` 等）。

### MVP 与工作量
- 这是**最大的一块**，本身够一个完整里程碑（2-3 周量级）。
- MVP 可裁到："给定一个小需求 → 引导需求分析对话 → AI 生成带雷代码 → 学生审查修复"
  一条最小闭环，先不做完整系统设计。即便如此也约 1 周。
### 风险
- 新的引导状态机（需求分析阶段）要重新设计，不能直接套调试六阶段。
- "AI 生成带教学 Bug 的代码"要可控、可判定——比埋雷题更难保证质量。
### 依赖
- 复用现有埋雷/事件/画像。是"横向扩玩法"，不阻塞其他方向。适合作为下一个大里程碑。

## 方向四 · 画像/推荐智能化（为长期"懂每个学生"打底）

### 痛点
推荐现在是**规则贪心**（profile.recommend_patterns）。设计文档 07 明说要留给
"遗忘曲线 / 贝叶斯知识追踪(BKT) / 自适应难度"——这些才是让系统真正"懂每个学生、
预测他该学什么"的东西，现在一个都没做。复习队列也只是固定 SM-2 阶梯。

### 做什么（渐进，每步都是可替换的派生函数）
- **4.1 遗忘曲线 → 更聪明的复习排程**：现在复习间隔是固定阶梯 [2,4,7,15]。
  升级：按每个学生每个知识点的"成功/失败历史"动态算保留度，到期时机个性化。
  纯派生，只改 review.py 一个函数（架构早留好了这个口）。
- **4.2 贝叶斯知识追踪（BKT）估掌握概率**：用 execution_events 序列估"这个知识点
  真正掌握的概率"，替代现在的离散状态（未接触/已解决/已内化）。让画像从"档位"变"概率"。
- **4.3 自适应难度**：据 BKT 掌握概率 + 最近发展区，动态选下一题难度（不太难不太易）。

### MVP 与工作量
- MVP = 4.1（遗忘曲线复习排程）——最独立、收益直观、只动 review.py。约 1 天。
- 4.2 BKT 约 2-3 天（要建模 + 调参 + 验证，且解释性要够让学生信）。
- 4.3 依赖 4.2。
### 风险
- **可解释性**：BKT 是概率模型，但 ACP 主打"诚实画像、每个数字可下钻"。
  概率化不能牺牲"学生能看懂为什么"。这是设计难点，不是技术难点。
- 调参需要真实数据——现在数据量小，模型可能不准。宜等有一批真实使用数据后再上 4.2/4.3。
### 依赖
- 4.1 可立即做。4.2/4.3 建议等真实用户数据积累后——否则模型没数据可学，是空转。

## 汇总建议（拍板参考）

| 方向 | 见效 | 工作量 | 风险 | 建议时机 |
|---|---|---|---|---|
| 一 · 过程数据活起来 | 快、惊艳 | 小（半天起） | 低 | **最该先做** |
| 二 · 情感/陪伴层 | 中、动人 | 中（1-2天） | 中（全在分寸） | 方向一之后 |
| 三 · Vibe Coding | 大、扩边界 | 大（1周+） | 中高 | 下一个大里程碑 |
| 四 · 画像智能化 | 慢、打底 | 中-大 | 中（可解释性+缺数据） | 4.1 可做；4.2+ 等真实数据 |

**我的推荐路径**：先做**方向一**（把已挖出的过程数据变成体验，投入小回报大）→ 
再做**方向二 MVP**（情感层，让产品有温度，正好是你的长处）→ 
方向三作为下一个独立大里程碑 → 方向四的 4.1 随手可做、4.2+ 等数据。

> 每个方向真正动手前，会再出一份该方向的**专项计划**（像 M3b/M4 那样含决策点），你评审后再写代码。

# v2「过程化编程学习系统」升级计划（2026-07-05）

依据同日体检 → [`../审计/2026-07-05-全面体检-架构与过程化评审.md`](../审计/2026-07-05-全面体检-架构与过程化评审.md)。

**设计总原则：事件流 schema 不动（铁律），在它两侧加「代码快照」和「课程结构」；先还债后上新——安全/并发/身份不做完，不许写新功能。**

## 0. MVP 验收线（一句话）

> 一个班 30 人可以**安全**同时用；每次 run/submit 留下**代码快照**；学生与教师都能**回放**任意一道题的解题过程；题目按**单元**组织。

明确不进 MVP：多语言、多文件、stdin 交互题、教师批注、RL 选题、情绪文本推断。

## 2. 数据库增量（events / execution_events / capability_scores / knowledge_states 四表不动）

```sql
-- 真实身份（替代自报 id；顺手修「登录后记录没了」）
students(id TEXT PK, name TEXT, class_id TEXT, token_hash TEXT, created_at)

-- ★过程化核心：每次 run/submit 的代码快照
code_snapshots(
  id TEXT PK, session_id TEXT idx, execution_event_id TEXT,   -- 与观测事实一一对应
  code TEXT, diff_stats JSON,   -- {lines_changed, touched_mine_line: bool}
  seq INT, timestamp TEXT)

-- 对话消息独立成表（替代 session.history 整块 JSON：治并发丢写 + 无限膨胀）
session_messages(id PK, session_id idx, seq INT, role TEXT, content TEXT, kind TEXT, created_at)

-- 课程结构
units(id PK, name, "order", description)
unit_items(unit_id, pattern_id, "order", required BOOL, PK(unit_id, pattern_id))
unit_progress(student_id, unit_id, state TEXT, updated_at, PK(student_id, unit_id))

-- tutor_sessions 增列（结束 manifest 寄存 mode 的权宜）
ALTER TABLE tutor_sessions ADD COLUMN mode TEXT DEFAULT 'debug';
ALTER TABLE tutor_sessions ADD COLUMN updated_at TEXT;  -- active-sessions 排序不再查事件表
```

数据库近期仍 SQLite（开 WAL），但立 Alembic、留好切 Postgres 的路（config 已有 DATABASE_URL）。

## 3. 接口增量（现有端点全保留）

```
POST /api/auth/login              {student_id, name?} → {token}    # 轻量 token，非密码
  · 现有 /students/{id}/* 改从 token 取 id；路径参数仅教师/admin 可用（关 IDOR #3）
GET  /api/sessions/{id}/replay    # ★回放：快照链 + 执行结果 + 对话按 seq 合并
GET  /api/curriculum              # 单元列表 + 本人进度
GET  /api/teacher/class/{id}/overview          # 班级：单元进度/卡点/求助率（复用画像派生）
GET  /api/teacher/students/{id}/replay/{sid}
改造：POST /sessions/{id}/messages 支持 SSE 流式
```

## 4. 前端页面

保留：大厅 / Arena / Coop / Profile / Timeline / QuestionTraining。新增两页：

1. **地图页 `/map`**：单元→关卡棋盘（替代平铺题目列表）；已内化打勾、复习到期标记（复用 review-queue）。大厅瘦身为「继续上次 + 今日推荐 + 今日复习」三卡。
2. **回放页 `/replay/:sessionId`**：左侧快照 diff 步进器（v1→v2→…），右侧对应时刻的运行结果与对话。这是「过程化」给学生和教师的可见交付物，也是 Timeline Episode 的下钻终点。

## 5. 导师策略（演进而非重写，六阶段双层原样保留）

1. **喂 diff 给导师**：④修复失败回流附「本次 vs 上次提交」diff 摘要（改了哪几行、雷行动没动）。REPAIR_LAYER 据此区分「盲改」（Independent_Debug 负向的客观依据）和「定向改错」。比塞整段代码省 token、更准。
2. **回复与判定拆两步**（可选）：先流式输出 reply，再轻量调用产出结构化判定——解决等完整 JSON 才显示的延迟。
3. **策略外置**：STAGES/门控阈值/剧本挪 `tutor/prompts.py` + policy 配置，为按学生分层（零基础/有基础不同剧本）留位。

## 6. 两周排期

### 第 1 周 · M1 还债（安全/并发/身份/迁移）——质量门，不过不上新

- [x] **D1–2 沙箱容器化 ✅（2026-07-05 完成）**：docker 跑 `python:3.12-slim`（`--network none --memory 128m --memory-swap 128m --pids-limit 64 --cpus 1.0 --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges --user 65534`），代码走 stdin + 容器内 GNU timeout 限时 + 外层 kill 兜底。sandbox.py 接口（run_code/RunResult/normalize_output）不变；`ACP_SANDBOX=docker/subprocess/auto` 三档，无 docker 自动降级 subprocess。`/api/health` 暴露 `sandbox` 后端供线上自检。逃逸验证 6 条全过（读库/偷 key/出网/死循环/fork 炸弹/写根），主套件 84→90 过 0 败（新增 6 隔离测试，docker 不可用则跳过）。Dockerfile 装 docker.io CLI；部署文档加 socket 挂载 + 预拉镜像说明。
  - **拍板结果**：docker 挂载方式 = 宿主 socket 直挂（`-v /var/run/docker.sock`，sibling-container 模式）。主服务本身受信，仅学生代码在嵌套的锁死子容器里跑。
- [x] **D2–3 身份与授权 ✅（2026-07-05 完成）**：`app/security.py` HMAC 自签无状态 token（零新依赖，secret 取 `ACP_AUTH_SECRET` 或 `.auth_secret` 持久化 + gitignore）；`students` 表；`/api/auth/login`（无密码，输学号 upsert + 签发 token）；`current_student` 依赖从 `Authorization: Bearer` 解学号；`require_self` 越权门。全部 `/students/{id}/*` + 会话/coop/diagnose 端点接入——**身份只认 token，不再信 URL/body 自报的 student_id**（关审计 #3 IDOR）。前端 api.js 带 Authorization、401 自动回身份页；App.vue 身份页调 login（async + 进入中态 + 错误提示）。端到端验证：无 token→401、看他人→403、坏 token→401、本人放行、建会话身份取自 token。测试 90→93（+token round-trip/看他人画像 403/操作他人会话 403）。
  - **拍板结果**：安全档位 = 方案 A（无密码 + 签名 token）。防外部遍历/脱库（IDOR），不防「知道学号的同学互相冒充」——学号班内半公开、冒充无实质收益。将来要防冒充，login 加一步 PIN 即可，token 层不动。
  - **「登录后记录没了」根因 = id 前后对不上**：现在统一走 login 签发，token 与 id 绑定一致；旧随机 id 走「继续沿用这份记录」用该 id 登录换 token，保留原进度。
  - **遗留给 D3-4**：students 表目前靠 create_all 启动时建；#9 CORS 换线上域名待部署时做。
- [x] **D3–4 迁移体系 ✅（2026-07-05 完成，部分 resequence）**：Alembic 立起来——`env.py` 接 `Base.metadata` + 运行时同源 `DATABASE_URL`；baseline 迁移（autogenerate 全 6 表）+ 现有 dev db 已 stamp；`init_db` 从裸 `create_all` 改为 `alembic upgrade head`，含**老库纳管桥**（有表但无 `alembic_version` → 先 stamp baseline 再 upgrade，不会重复建表；alembic 异常兜底 create_all）。已验证全新空库/老库（无 updated_at 列）两条启动路径都正确迁移 + 回填。新增 `tutor_sessions.updated_at` 列 + 迁移（nullable + 回填 created_at，避开 SQLite NOT NULL 新列限制）+ 变更路径 `touch()` dual-write（run_turn/run_and_inject/submit/coop message&resolve）；active-sessions 排序改用它，去掉每会话回查 ExecutionEvent（治 R4 一部分）。WAL + busy_timeout 从 D4-5 前移到 `db.py`（并发缓解，1 处）。测试仍 93 过 0 败。
  - **resequence（工程判断）**：`session_messages` 拆表**移到 M2（代码快照）一起做**。理由：① 拆表本身不解决并发丢写（history JSON 仍读改写整块）——**并发安全**由 D4-5 会话锁 + 已上的 WAL 更直接、更省地兜住；② session_messages 的独有价值（history 无限膨胀 + 逐条回放粒度）只被 M2/M3 回放消费，故把动 tutor.py（皇冠资产，`.history` 15 处引用）的手术**并到 M2 一次做完**，不在 M1 反复动它、徒增回归面。
  - **mode 列**：暂不迁（仍寄存 `manifest["mode"]`，工作正常）；将来清理 manifest 时并入。
- [x] **D4–5 并发 ✅（2026-07-05 完成，async 缩到 threadpool 抬闸）**：`app/concurrency.py` per-session 回合锁（threading.Lock 分桶 + guard dict）；以 FastAPI yield-依赖 `turn_lock` 挂在所有写会话的端点（send_message/submit/run/abandon/coop run&message&resolve）——串行化同会话并发，**堵丢写 R2 + submit TOCTOU 审计 #12**（第二个请求进来已见 fixed，早返回）。lifespan 抬 anyio threadpool 到 64（一个 LLM 对话最长占一线程 ~30s，防满班时对话请求占满默认 40 令牌拖慢快端点）。WAL + busy_timeout 已在 D3-4 上。测试 93→95（同会话串行无丢写 / 不同会话不同锁）。
  - **async 全量重写 defer（工程判断）**：端点仍同步（跑在 threadpool，本就不阻塞事件循环）。全量 async 需把 profile/event_engine/tutor 全部 sync Session 换 async SQLAlchemy——大手术、动皇冠资产 tutor.py，且对「一个班 30 人」目标属过度优化。同步端点 + 会话锁 + WAL + threadpool 抬闸对该量级已足够。真到需要更高并发时，async 单独立里程碑。
  - **单进程限制**：内存锁只在单 uvicorn worker 有效。当前 Render/VPS 单实例单 worker 成立；将来多 worker/多机须换 DB 级锁（tutor_sessions.busy 列 + 原子 UPDATE）——已在 concurrency.py 注明。
- [ ] **周末缓冲**：84 测试迁 pytest 跑法（断言体不动）；新增两组测试：沙箱逃逸（读文件/发网络/fork）+ 越权访问。

**M1 验收**：学生代码读不到 acp.db、出不了网；无 token 访问他人数据一律 403；两个并发消息不丢写；`alembic upgrade head` 可从零建库。

## 7. 风险与决策点

| 决策点 | 建议 | 何时拍板 |
|---|---|---|
| VPS 上 docker-in-docker 还是宿主 docker | 宿主 docker socket 直挂（服务本身不进容器时最简单） | D1 动手前 |
| session_messages 双写期多久 | 一版兼容（读旧 history 兜底），下版删 | M1 结束 |
| 教师身份怎么做 | MVP 先 admin token，学期化再做教师账号 | M4 |
| #18 画像虚高修法（A 全子能力入分母 / B 置信按能力数） | 与地图页一起看视觉语境再定 | M3b |

**节奏红线**：第 1 周是质量门——M1 没验收就开始写快照/课程，等于把新功能盖在会丢数据、能被脱库的地基上。

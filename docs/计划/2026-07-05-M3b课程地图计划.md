## 0. 目标（一句话）

把 21 道平铺题组织成**「单元 → 关卡」的可见地图**：学生能看到全局、自主选关、看到每关进度（未接触/已解决/已内化/复习到期）；给老师「按周布置」的结构抓手。补上「智能开题」看不见全局的短板。

## 1. 现状（探查结论）

- 题库 21 道入库：boundary 5 · loop 6 · null 7(含 shared) · arithmetic 3；难度 L1–L3（+2 道 GEN 待审，不入单元）。
- 大厅（Arena）已瘦身：「智能开一题」+「接着做」档案面板 +「查看推荐与题库 →」（指向 Profile）。**不再平铺题库**。
- 推荐在 Profile「推荐」tab；复习队列在 Timeline 顶部；进度靠 `knowledge_states`（未接触/已接触/已解决/已内化）。

## 2. 单元划分（21 道 → 4 单元，按 Bug 类型分，单元内按难度升序＝关卡顺序）

| 单元 | 主题 | 题（按难度） | 练的思维 |
|---|---|---|---|
| U1 边界与差一 | boundary | 001(L1) 003(L1) 002(L2) 004(L2) 005(L3) | 下标/长度、空集合防护 |
| U2 循环的陷阱 | loop | 001(L1) 002(L2) 003(L2) 004(L2) 006(L2) 005(L3) | 循环终止、控制流语义 |
| U3 空值与共享 | null + shared | 001(L2) 002(L2) 003(L2) 006(L2) 004(L3) 005(L3) SHARED-001(L2) | None 防护、别名/共享状态 |
| U4 算术的坑 | arithmetic | 003(L1) 002(L1) 001(L1) | 初值/取模/整除 |

> 按类型分单元＝一个单元练透一类思维默认值（呼应 `thinking_pattern`），教学连贯性最好。

## 3. 关键设计决策（★需你拍板）

### 决策 A：单元怎么建模？
- **A1（推荐）配置 + 纯派生，零新表**：单元定义写一个 `curriculum.yaml`（像 patterns 一样静态配置：单元名/顺序/含哪些题）；单元进度**纯从 `knowledge_states` 派生**（该单元几道已内化/已解决）。符合项目「静态配置 + 派生视图」既有哲学，零迁移、易调整单元。
- A2 三张表（上级计划原写法：units/unit_items/unit_progress）：更"正规"，但课程是静态的、进度可派生，建表+迁移+维护是额外负担，unit_progress 甚至和 knowledge_states 重复。

### 决策 B：关卡解锁策略？
- **B1（推荐）全开放 + 推荐顺序标注**：所有关卡可点，按单元/难度排出推荐路径，标进度徽章，不硬锁。符合项目「不放水但不强迫」调性，也不挡老手。
- B2 软解锁：前一关「已解决」才亮下一关。更有闯关感，但可能挡住想跳着做的学生、也和「智能开题」自由选并存别扭。

### 决策 C：大厅这轮动不动？
- **C1（推荐）只加入口，不重排**：新增地图页 `/map`，导航加「课程地图」入口，大厅 Arena 基本不动（它是 1504 行大文件）。大厅三卡重排（继续上次+今日推荐+今日复习）留到 **Arena 拆组件那批**（和审计 #14-17 一起，见上级计划缓冲项），避免现在动大文件引入回归。
- C2 这轮就把大厅重排成三卡：交付更完整，但动 Arena 风险高、超出 M3b 聚焦范围。

## 4. MVP 范围（本轮做）

- `backend/app/curriculum.py`（或 config）：加载 `curriculum.yaml` 单元定义。
- `services` 派生：`build_curriculum(db, student_id)` → 单元列表，每单元含题目 + 每题状态（knowledge_state）+ 复习到期标记（复用 `review.due_queue`）+ 单元汇总（x/y 已解决、z 已内化）。
- `GET /api/curriculum`（token 身份，含个人进度）。
- 前端 `Map.vue` + 路由 `/map`：单元卡纵向、关卡横向棋盘、状态徽章（未接触/已解决 ✓/已内化 ★/复习到期 🔁）、点关卡→进 Arena（复用 `?start=pattern_id`）；导航加入口。
- 测试：build_curriculum 分组正确、进度派生正确、越权（含身份）。

## 5. 不做（这轮明确排除）

- 大厅 Arena 三卡重排（→ Arena 拆组件批）。
- 强制解锁门槛（除非决策 B 选 B2）。
- 老师端按单元布置（→ M4 教师端）。
- 单元编辑后台（单元定义先手工改 yaml）。

## 6. 步骤与验收

1. 写 `curriculum.yaml`（4 单元定义）+ 加载器 → commit。
2. `build_curriculum` 派生 + 测试 → commit。
3. `GET /api/curriculum` 端点 + 越权测试 → commit。
4. 前端 `Map.vue` + 路由 + 导航入口 + 构建通过 → commit。
5. 端到端验证（做一道题→地图上该关变「已解决 ✓」→复习到期显 🔁）→ 合并 main + push。
6. 更新工作日志 + 勾选上级计划。

**验收**：新学生进来能看到 4 单元 21 关的地图；每关状态实时反映 knowledge_states；点关卡能进对应题；已内化的打 ★、复习到期的标 🔁。

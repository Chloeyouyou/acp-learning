# M4 · 教师端最小视图 计划（2026-07-05）

上级计划：`2026-07-05-v2过程化升级计划.md` 第 2 周 M4。动手前先定这份，评审通过再写代码。

## 0. 目标（一句话）

给老师**一页能一眼看全班**的只读总览：每个学生做到哪、解决/内化了几题、最近活跃、正卡在哪。让系统能进真实课堂——决策者最关心的「老师能看到什么」有了答案。

## 1. 现状（探查结论）

- 已有 admin 机制：`ACP_ADMIN_TOKEN` 环境变量 + `?token=` 常量时间比较（`admin_list_sessions` 端点，能按学号看某生完整会话史）。
- `Student` 表有 `id/name/class_id`，但 **login 只写 id+name，`class_id` 目前全空**（没人填）。
- 现成派生可复用：`knowledge_states`（解决/内化数）、`presence_signals`（最近活跃）、active `TutorSession`（卡在哪题第几阶段）。

## 2. 教师总览：每个学生一行看什么

| 列 | 来源 |
|---|---|
| 学号 + 姓名 | Student 表 |
| 已解决 / 已内化 题数 | knowledge_states 派生 |
| 已接触（在学）题数 | knowledge_states |
| 最近活跃（几天前） | presence_signals |
| 正在进行 | active TutorSession（非 coop）最新一局的题名 + 阶段 |
| （可选）求助信号 | answer_begging 负事件计数——MVP 先不放，留字段 |

汇总排序：默认「最近活跃」倒序（老师先看最近在用的）。

## 3. 关键设计决策（★需你拍板）

### 决策 A：教师身份怎么鉴权？
- **A1（推荐）复用 `ACP_ADMIN_TOKEN`**：零新机制，老师页输这个 token 即进。缺点：这是能看所有对话史的"总钥匙"，放进浏览器有轻微风险——MVP 单一作者/老师可接受。
- A2 新加 `ACP_TEACHER_TOKEN`（只读总览、看不了完整对话）：权限更干净，但多一套机制。

### 决策 B：班级归属怎么办（class_id 现在是空的）？
- **B1（推荐）MVP 看全体学生 + 可选 `?class_id=` 过滤**：不改登录、不加摩擦。全校铺开、学生变多后，再让登录填班级/或后台导入名单。查询支持传 class_id 就按班过滤，不传就全体。
- B2 现在就给学生登录加「班级」选择：能立刻分班，但给登录加了摩擦、且要改前端身份页。

### 决策 C：教师页怎么进 / 形态？
- **C1（推荐）独立隐藏路由 `/teacher`，不挂学生导航**：老师直接访问 URL，页面里输一次 token（存 localStorage），拉总览渲染表格。学生端完全看不到入口。
- C2 纯 JSON 端点（不做页面）：最省，但老师得自己看 JSON，不友好。

### 决策 D：要不要「钻取」（点某学生看详情）？
- **D1（推荐）MVP 只做总览表格**，钻取（看某生画像/某题回放）留下一步。表格里可先把「看 TA 的对话史」链到已有 `admin_list_sessions`。
- D2 这轮就做钻取到画像/回放：更完整，但超出「最小视图」范围、工作量翻倍。

## 4. MVP 范围（本轮做）

- `services/teacher.py`：`build_class_overview(db, class_id=None)` —— 遍历 students（可按 class_id 过滤），每人聚合上面那几列（复用 knowledge_states/presence/active-session 派生）。
- `GET /api/teacher/overview?token=xxx[&class_id=yyy]`：admin token 校验（复用 `admin_list_sessions` 那套 hmac 比较）。
- 前端 `Teacher.vue` + 路由 `/teacher`（不挂导航）：首访输 token → 存本地 → 拉总览 → 极简表格（可按活跃/进度排序）。
- 测试：build_class_overview 聚合正确、class_id 过滤、无 token/错 token → 403。

## 5. 不做（这轮明确排除）

- 钻取到某生画像/回放（→ 下一步；表格先链到已有 admin 会话史）。
- 学生登录加班级选择（→ 需要分班时再做）。
- 教师账号体系 / 布置作业 / 导出报表（→ 更后面）。

## 6. 步骤与验收

1. `services/teacher.py` build_class_overview + 测试 → commit。
2. `GET /api/teacher/overview`（token 校验 + class_id 过滤）+ 测试 → commit。
3. 前端 `Teacher.vue` + 路由 + token 输入 → 构建通过 → commit。
4. 端到端（造 2 个学生、各做题 → /teacher 表格正确反映 → 无 token 403）→ 合并 main + push。
5. 更新工作日志 + 勾选上级计划。

**验收**：设了 `ACP_ADMIN_TOKEN` 后，老师访问 `/teacher` 输 token → 看到全班每人「解决/内化/最近活跃/正卡在哪」一张表；无 token/错 token 进不去。

## 7. 决策默认值（你不特别说就按推荐走）

A1（复用 admin token） · B1（看全体 + 可选 class_id） · C1（隐藏 /teacher 页） · D1（只总览、钻取留后续）。

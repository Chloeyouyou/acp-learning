# ACP 主线二轮：续学决策与回放归拢（2026-07-15）

## 目标

在第一轮“前台减法、后台归拢”基础上，再补齐两个会直接影响产品成熟度的断点：

1. 用户进入“我的成长”时，不需要自己在未完成练习、到期复习和新题推荐之间判断，页面始终只给一个优先级明确的下一步。
2. 过程回放不再默认铺开全部技术流水，而是由后端从真实事件中派生主线，先展示关键动作与转折；完整过程仍可按需展开。

主线保持为：

```text
继续未完成 → 到期复习 → 画像推荐 → 开始新练习
                          ↓
真实动作 → 关键转折 → 学生总结 → 完整审计过程
```

## 改造范围

### M1 · 单一下一步

- “我的成长”同时读取未完成会话、复习队列和推荐题，但只展示一个行动卡。
- 优先级固定为：未完成会话 > 到期复习 > 个性化推荐 > 新练习。
- 其余候选不并排争夺注意力，只用一句话说明稍后还有多少项。
- 不新增接口，不改变推荐、复习和续做的既有业务规则。

### M2 · 回放主线派生

- 后端在现有 append-only 回放步骤上增加纯派生 `mainline` 标记和原因，不写库、不改事件结构。
- 主线纳入：第一次/最后一次真实运行、已有转折标注、学生观察与总结、导师换讲法。
- 学生端和教师端共用同一份主线标记，避免两端各自猜测重点。
- 前端默认显示主线，可切换到完整过程；技术凭据和所有原始步骤仍保留。

### M3 · 验证

- 后端测试覆盖主线选择规则，以及回放返回主线数量。
- Playwright 覆盖“我的成长只有一个下一步”和“主线/完整过程切换”。
- 生产构建、后端全量回归、浏览器关键链路全部通过。

## 边界

- 不新增数据库字段或迁移。
- 不修改六阶段状态机、知返教学策略、能力计分和动作治理。
- 不删除任何回放事实；`mainline` 只是可重算的阅读层。
- 不把推荐、复习、续做合并为新的后端决策黑箱，优先级在前端保持清晰可见。

## 回滚

- 单一下一步可独立恢复为原复习列表，不影响数据。
- 回放可忽略 `mainline` 标记恢复全量展示，原始 `steps` 契约保持兼容。

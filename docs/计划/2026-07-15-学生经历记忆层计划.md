# 学生经历记忆层计划（2026-07-15）

> 借鉴来源：土豆分支（F:\下载\youyouskill）的三层记忆设计与轻量检索算法。
> 对照结论：ACP 已有第一层（能力画像=抽象层）和第三层（六阶段会话状态），唯独缺
> 第二层——跨会话的「这个学生具体怎么踩坑、怎么走出来」的经历记忆。导师每轮只看
> 当前会话 + Ground Truth，说不出「你上次在 XX 关也遇到过类似的错」。

## 目标

给知返补上「与这个学生的共同经历」：关卡内化结算时沉淀一条经历，之后的新关卡里
按相关度召回 1~2 条注入导师 prompt，让引导能接上学生的个人历史（共情 + 方法迁移），
而不是每关都当陌生人。

## 约束与决策

- **铁律不动**：`events` / `execution_events` / `capability_scores` / `knowledge_states`
  schema 不动；新表 `student_experiences` 为第 4 张 append-only 表（只 INSERT）。
- **经历摘要确定性生成，不用 LLM**：ACP 的结构化事实（pattern 元数据、execution_events
  的 error_family 序列、提示级别、卡顿轮数、内化三轴）足够拼出高质量摘要——零成本、
  可测试、天然不含 expected_fix（土豆分支「保存时标注检索关键词」的思路，但用规则实现；
  LLM 润色留作未来增强）。
- **检索算法移植土豆分支 branch-logic.ts**：中文虚词过滤 + 一/二元语法覆盖率打分、
  按查询规模归一化（长记忆不天然占优）、`RELEVANCE_FLOOR` 门槛宁可空手不带跑题记忆。
  无向量库，纯 Python ~80 行。
- **泄题双保险**（沿用土豆分支「prompt 硬规则 + 落库硬门控」模式）：
  1. 落库端：摘要模板不含 expected_fix / fix_check / buggy_code 任何片段（有测试锁死）；
  2. 注入端 prompt 硬规则：经历只作共情与方法参照；①发现/②定位阶段绝不点破当前题
     与过往经历的成因联系；绝不复述过往题目的修复代码。
  3. 现有 reply guard（`assess_teaching_reply`）继续兜底最终出站。
- **召回排除当前 pattern_id**：变式迁移检验时不能用旧经历剧透同一题的根因。
- **coop 会话隔离**：AI 共脑调试（is_coop）不记录、不召回，维持「不污染画像」的既有边界。
- 查询词 = 当前雷的 root_cause + cognitive_root + knowledge_points + category + symptom，
  会话内固定，每轮召回结果一致。

## 实施步骤与验收

### M1 · 经历记忆层（主体）

- `models.py` 新增 `StudentExperience`（id / student_id / session_id / pattern_id /
  summary / keywords JSON / facts JSON / created_at），配 Alembic 迁移（人工检查 DDL，
  `alembic check` 无 drift）。
- 新服务 `services/experience.py`：
  - 纯逻辑：`relevance_score(query, doc)`（虚词过滤 + n-gram 覆盖率）、`RELEVANCE_FLOOR`；
  - `record_on_completion(db, session)`：内化结算时确定性生成摘要 + 关键词落库；
  - `recall(db, student_id, query, exclude_pattern_id)` → 过门槛 top2。
- `tutor.py` 接线：结算处（mine_status→internalized）调 record；`run_turn` 召回后以
  `EXPERIENCE_LAYER_TEMPLATE` 注入 system（带上面第 2 条硬规则）。

验收：
- 纯逻辑测试：相关词召回 / 纯虚词重叠不召回 / 门槛以下空手而归；
- 内化结算后落库一条经历，摘要含题名与错误家族、**不含 expected_fix 任何片段**；
- 新会话（不同 pattern）`run_turn` 的 system 含过往经历段；同 pattern 被排除；
- coop 会话不记录不召回；无经历的新学生行为与现状完全一致（向后兼容）。

### M2 · 导师红线对抗评测集（借鉴 evaluation_cases.jsonl 模式）

- 新增 `backend/eval_tutor_redline.py`（真连 LLM、花钱，独立于 run_tests.py 手动跑，
  仿 `eval_question_training.py`）：固定诱导用例（直接要答案 / 冒充老师授权 / 求贴
  正确代码 / L5 哀求 / 让复述修复行……），断言守门后的最终 reply 无 direct_fix_leak。

验收：脚本可跑、逐条输出 通过/违规+守门拦截情况；改 SYSTEM_TEMPLATE 后有回归抓手。

### M3 · LLM 不可用兜底升级（小改）

- `run_turn` 的异常兜底语从固定「走神了」升级为 `safe_guard_reply(session.stage)`
  （前缀保留一句道歉说明），无 Key/断网时学生仍能收到当前阶段的确定性引导。

验收：stub 抛异常时回复含对应阶段的安全问题，状态不变、不落 LLM 事件。

## 回滚边界

- `student_experiences` 是独立新表，撤下注入段（模板置空）即可完全回到现状；
- 注入只改 system prompt，不参与任何状态机跃迁判定与事件产出；
- 迁移只 ADD TABLE，可安全 downgrade。
